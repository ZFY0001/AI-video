## 4. 第一轮建立的关键不变量

1. **能力诚实**：评审结果必须带 `review_mode`；不可用/未接入的后端在目录中明确标注；“测试”只做连通性探测，不生成收费样片。
2. **不静默覆盖**：项目修改走 revision，冲突返回 409；片段指纹为 `unknown/stale` 时拒绝复用并说明原因，而不是拼旧片。
3. **缓存按内容失效**：片段指纹覆盖镜头文案、提示词、主体引用、题材/风格/画幅、色板、预览档位、安全区、provider 链与目标分辨率；排除时长与起点。
4. **配置单一来源**：渲染配置快照（含色板）随项目/任务传递，不依赖请求默认值。
5. **导出可追溯**：导出指纹由源片与品牌指纹共同决定；改品牌或字体后旧导出自然失效。

## 6. 已接受边界（请不要重复当作缺陷）

1. **F8 没有真实收费供应商适配器**：云端出图/视频/TTS 均未接入；能力目录会显示“未接入/不可用”。
2. **费用台账是估价，不是账单**：单价为代码内保守估算，所有事件带 `estimated=true`；没有供应商侧计费幂等，也没有跨任务预算预留。
3. **预算闸只对整片正式拍摄的云端视频生效**：本机绘制、ComfyUI、预览、重合成不应被假想单价拦截；云端适配器未接入时估价为 0。
4. **品牌模板只作用于 9:16 / 1:1 派生导出**：16:9 母版不叠加品牌，这是有意边界。
5. **真实 ComfyUI / GPU / 云端 VLM / 付费 TTS 未实测**：VLM 仅用本地 Mock OpenAI 服务验证了请求体与失败回落。
6. **没有真实拖拽交互测试**：波形调轴、裁剪等靠代码与 DOM 操作验证。
7. **没有 Git 基线、没有 CI**：依赖仍为宽下界，干净构建与依赖锁定属于第二轮工程化事项。
8. **真实出片质量未做主观验收**：只验证链路、文件产出与可解释质检，不声称画面质量达标。

## 7. 建议重点审计的问题（比重复验收更有价值）

以下是我认为最可能藏着真实缺陷的地方，建议逐条给结论：

1. **片段指纹是否漏了影响画面的输入**：当前只哈希 `subject_refs` 的 ID，不哈希参考图文件内容；只哈希 `workflow_id`，不哈希工作流文件内容；provider 只记录 `name:provider_id`，不记录模型/地址等配置。更换同一主体的参考图、修改 ComfyUI 工作流或切换模型后，旧片段是否会被错误命中？见 `pipeline/clipcache.py` 与 `pipeline/pipeline.py` 的 `_clip_key`。
2. **预算闸是否可绕过**：`guard_budget` 只在整片正式拍摄时调用；单镜重拍、重试复用任务时没有重新过闸。云端适配器接入后，这是否构成超预算入口？见 `server/plan.py` 的 `_start_render`。
3. **版本与资产并发**：色板保存、品牌保存、字幕保存都改 `meta.json`，是否都经过同一 revision/原子写路径？品牌版本与项目 revision 分离是否会带来覆盖窗口？
4. **新增路由的归属与路径安全**：参考图、品牌 Logo、批量导出、导出文件下载是否都校验项目归属？上传文件名、Logo 路径是否存在穿越或覆盖风险？
5. **F7 裁切规则的字幕风险**：`crop` 明确可能切掉靠边字幕，界面有提示；需要确认“提示”是否足够，还是应在导出前做安全区检测。
6. **任务重试的幂等边界**：重试会重跑整条任务，已完成的步骤能否复用？云端调用是否会在“任务已提交但响应丢失”时重复计费？
7. **质检证据的可信度**：技术检查的阈值（黑屏、对比度、尺寸）是否会误判？VLM 失败回落 `simulated` 后，UI 是否所有位置都能区分？
8. **前端保存屏障的覆盖范围**：分镜、字幕、色板、品牌是否都经过 `flushSaves` / 冲突刷新？快速连续操作是否有丢更新窗口？
