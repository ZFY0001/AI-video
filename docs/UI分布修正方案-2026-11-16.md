# UI 分布修正方案（设置页为重点）

日期：2026-11-16
对象：`YiYanStudio-V3-完整源码/一言片场-V3/web`
状态：**已落地并实测**。本文件既是方案，也是落地记录——每一条都给出改前/改后的实测数字与代码位置，未实测的部分单列在第 6 节。

## 1. 问题定性：不是"样式不好看"，是三条结构性缺陷

用户反馈"界面尤其是设置页很乱"。把设置页在 1440×900 与 420×900 两个视口量完之后，"乱"可以拆成三个可测量的根因，而不是审美判断：

| 根因 | 改前实测 | 后果 |
|---|---|---|
| **R1 主操作埋在长页底部** | 设置页主内容高 2268px，"保存到 .env" 在文档流最末尾 | 改一个 Key 要滚 2000+px 才能保存；中途滚动位置丢失后找不到按钮 |
| **R2 主次内容同列堆叠** | 环境体检（只读诊断）与密钥表单（可写）在同一列顺序排布，诊断原始输出默认展开 | 表单被大段等宽诊断文本切断，视觉重心在"读"而不在"填" |
| **R3 说明文字对比度不足** | 亮色 `--color-ink-mute` 在玻璃面板上 **2.87:1**，`--color-mint` **2.74:1**；暗色 ink-mute **4.12:1** | 11.5px 的提示文字基本读不清，用户只能靠猜——这是"乱"的主观来源 |

R3 是最容易被忽略的一条：对比度不足时，信息层级在视觉上塌成一片，页面看起来"密而乱"，但改间距、改圆角都治不好。

## 2. 修正方案与落地结果

### 2.1 R1 → 常驻操作条（sticky action bar）

**方案**：把"锚点导航 + 待写入计数 + 放弃/保存"提为一条常驻横条，吸顶在导航栏正下方，滚到任何位置都够得着。保存按钮不再依赖滚动位置。

**落地**：[SettingsPage.tsx:419](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L419)

```tsx
<div className="sticky top-[100px] z-30 -mx-4 mb-4 border-y border-[var(--ring)]
                bg-[var(--nav-bg)] px-4 py-2 backdrop-blur-2xl sm:-mx-6 sm:px-6 md:top-[56px]">
```

- 窄屏吸顶 `top-[100px]`（导航实测高 101px），`md` 以上 `top-[56px]`（导航实测高 57px）。
- 锚点导航自身 `overflow-x-auto` + `scroll-thin`，四个分区在 420px 下横向可滑，不挤压保存按钮。
- 保存按钮 `shrink-0`，永远在视口内；`disabled={saving || !user || dirty === 0}`，未登录时 title 明示"写入配置需要登录"。
- 待写入计数 `dirtyLabel` 在 `lg` 以上显示，窄屏靠按钮态表达。

**实测**：420px 视口下保存按钮簇完整落在视口内，无横向溢出（`documentElement.clientWidth === body.scrollWidth === 420`）。

### 2.2 R2 → 表单优先的双列分布 + 诊断收起

**方案**：桌面端把"可写表单"与"只读体检"分成两列，表单在左（主），体检在右（次）且自滚动吸顶；原始诊断输出默认收起。

**落地**：[SettingsPage.tsx:460](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L460)

```tsx
<div className="grid items-start gap-4 xl:grid-cols-[minmax(0,1fr)_330px]">
  <div className="min-w-0 space-y-4">   {/* 密钥与模型 / 生成器 / 费用台账 */}
  <aside className="scroll-thin scroll-mt-[176px] xl:sticky xl:top-[124px]
                    xl:max-h-[calc(100vh-148px)] xl:overflow-y-auto xl:scroll-mt-[124px]">
```

关键决策：

1. **DOM 顺序决定列位置**，不用 `order-*`。表单容器在前、体检 aside 在后，因此窄屏单列时表单天然先出现——不需要为移动端再写一套排序。
2. **体检列自滚动**（`max-h-[calc(100vh-148px)]` + `overflow-y-auto`），长诊断不会把整页撑高，也不会把表单推走。
3. **`minmax(0,1fr)`** 而非 `1fr`：防止表单内的等宽长字符串把列撑破。
4. **原始诊断进 `<details>`**（[SettingsPage.tsx:173](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L173)），默认收起，summary 用 `text-ink-mute` 弱化处理。
5. **密钥表单成对排布**：`grid gap-x-4 gap-y-3.5 sm:grid-cols-2`（[:513](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L513)），同一供应商的 Key 与模型并排，减少纵向长度。
6. **"生成器"与"费用台账"拆成两块独立面板**（原先合并标题"生成器与费用"），[:619](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L619) 与 [:673](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L673)。两件事的心智模型不同：一个是"能力目录/选谁出图"，一个是"花了多少钱/预算闸"，合并会让锚点导航失去意义。

**实测（1440×900）**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 主内容总高 | 2268px | **2068px** |
| 表单列宽 | — | 846px |
| 体检列宽 | — | 330px（clientH 752 / scrollH 961，自滚动生效） |
| 密钥面板宽 | — | 812px，输入成对 |

**实测（420×900）**：主内容高 3686px，`docScrollWidth === 420`，无横向溢出。

### 2.3 R3 → 文字令牌对比度重定标

**方案**：不动布局，只把三个文字令牌压到 WCAG AA（≥4.5:1）以上，并且要在**三种实际承载面**上都达标：页面底色 `--base-1`、玻璃面板 `--glass-panel`、凹陷区 `--sunk`。约束面是"最亮的那一面"（深色文字）与"最暗的那一面"（浅色文字），只测底色会漏判。

**落地**：[index.css:16](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css#L16) 与 [:81](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css#L81)

```css
/* 亮色 */
--color-ink-mute: #656d7e;   /* 原值在玻璃上只有 2.9:1 */
--color-mint:     #097676;
/* 暗色 */
--color-ink-mute: #8b93a7;   /* 原 #757d90 在最亮玻璃处只有 4.1:1 */
```

**实测对比度**（相对亮度 + alpha 合成，三面分别计算）：

| 令牌 | 主题 | base-1 | glass-panel | sunk |
|---|---|---|---|---|
| ink-mute | 亮 | **4.60** | **5.05** | **4.71** |
| mint | 亮 | **4.81** | **5.28** | **4.93** |
| ink-mute | 暗 | **6.54** | **5.52** | **5.96** |

改前对应值：亮色 ink-mute 2.87、mint 2.74；暗色 ink-mute 4.12。**现在全部文字令牌在两个主题、三种承载面上均 ≥4.6:1。**

层级没有被压平：`ink`（主文字）> `ink-dim`（次级）> `ink-mute`（说明）仍然拉开明显差距，暗色下 ink-mute 5.52 对 ink-dim 仍有可见区分。

### 2.4 锚点跳转落点（导航吸顶的配套必要条件）

吸顶导航 + 吸顶操作条会叠出 100~176px 的遮挡区。`scrollIntoView({block:'start'})` 默认把目标顶到视口 0px，标题会被吃掉。

**方案**：给每个锚点目标加 `scroll-margin-top`，值 = 导航高 + 操作条高 + 安全余量。

**落地**：三块面板与体检 aside 统一 `scroll-mt-[176px]`，`md` 以上 `md:scroll-mt-[124px]`；aside 在 `xl` 用 `xl:scroll-mt-[124px]`。跳转函数 [:388](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx#L388)：

```tsx
const jump = (key: SectionKey) => {
  setActive(key)
  document.getElementById(`settings-${key}`)?.scrollIntoView({ behavior: 'smooth', block: 'start' })
}
```

**实测落点**：

| 视口 | 遮挡区 | 面板落点 top | 余量 |
|---|---|---|---|
| 420 | 导航 0–101 + 操作条 100–159 | **176** | 16–17px |
| 1440 | 导航 0–57 + 操作条 56–105 | **124** | 19px |

`usage` 在 1440 下落到 663px——因为页面已到最大滚动位置，该面板完整可见，属正确行为而非落点错误。`aria-current` 随点击同步更新。

## 5. 探针口径说明（两次"疑似缺陷"实为测量假阳性）

审计过程中有两处看起来像 bug，实测后确认是**探针环境**造成的，不是代码缺陷。记录在此以免后续重复误判：

1. **平滑滚动"不动"**：页面 `visibilityState === "hidden"` 时浏览器暂停 smooth scroll 动画，`scrollTop` 永远停在 0。改用 `behavior:'instant'` 后面板精确落在 124px（= scroll-mt），证明落点逻辑正确。
2. **暗色主题"渲染成亮色文字"**（对比度算出 1.07）：同一原因暂停了 `transition: color .32s`，取到的是过渡中间值。注入 `*,*::before,*::after{transition:none!important;animation:none!important}` 后 body 颜色为 `rgb(242,245,251)`，正确。**真正的缺陷是令牌值本身（R3），不是主题切换。**

后续任何在后台标签页跑的视觉探针，都应先禁用过渡/动画再用 instant 滚动，否则结论不可信。
