## 1. 先说清楚：不是克隆剪映

一言片场是**分镜驱动的 AI 短片生成器**，剪映是**时间线驱动的通用剪辑器**。两者的核心资产不同：

| | 一言片场 | 剪映 |
|---|---|---|
| 创作起点 | 一句话 → 剧本 → 分镜 → 出图/出片 | 素材 + 时间线 |
| 时长权威 | 分镜时长 / 音乐（MV） | 用户拖拽 |
| 编辑对象 | 镜头（语义） | 帧/片段（像素） |

因此本方案只对标剪映中**能加固"分镜驱动"这条主线**的能力，**不**引入自由时间线。凡是会破坏"改一句话重拍整片"这一核心承诺的功能（逐帧剪辑、多层叠加、自由关键帧轨道），一律不做——见第 5 节。

---

## 2. 能力对照

| 剪映能力 | 本产品现状 | 差距定性 |
|---|---|---|
| 自动字幕（语音转写） | 字幕由台词文本推导，不读音频 | **真差距**：用户自带配音/音乐时无字幕依据 |
| 字幕样式/描边/位置 | 有基础烧录与品牌层；逐字高亮仅 painted 后端 | 能力有，但不统一、不可配置 |
| 关键帧动画（文字/贴纸） | 无 | 真差距 |
| 转场 | 无（硬切） | 真差距 |
| 速度曲线 | 无 | 真差距（但会动时长权威） |
| 智能重构画幅（主体跟踪） | 只有 fit/crop 两种固定规则 | 真差距 |
| 音频闪避（人声压音乐） | 有固定音乐增益，无 sidechain 闪避 | 部分差距 |
| 响度标准化 | 混音内有 loudnorm | 导出层未按平台标准 |
| 导出预设（平台规格/码率） | 三种画幅 × 两模式 | 缺码率/帧率/平台预设 |
| 节拍卡点 | **已有** `pipeline/beats.py` + 验证工具 | 已具备，需界面化 |
| 逐字卡拉 OK | **已有**（painted 后端）+ 验证工具 | 已具备，需跨后端 |
| 歌词/音乐 MV | **已有** `pipeline/lyrics.py` + 混音 | 已具备 |
| 模板复用 | **已有** 品牌模板 + 撤销 | 可扩展为工程模板 |
| 单镜重拍/预览 | **已有** | 已具备 |
| 成本台账/预算闸 | **已有**（F8 底座） | 已具备 |

**结论**：真正缺的是"**声音驱动的字幕**、**轻量动效**、**音频自动化**、**导出规格**"四块；节拍/卡拉OK/歌词/模板/重拍这些剪映卖点，本产品已有底座，缺的是**界面化与跨后端打通**。

## 3. 候选新功能（按优先级）

优先级判据：**是否加固分镜主线** × **实现成本** × **是否可诚实验证**。P0 = 直接补齐主线缺口；P1 = 提升成片质感；P2 = 锦上添花。

### C1 自动字幕：语音转写 + 断句 + 对轴（P0）

**剪映做法**：识别音频 → 断句 → 时间轴逐句对齐 → 可编辑。

**本产品缺口**：字幕文本来自 `shot.caption/narration`，时间来自镜头时间轴。一旦用户上传自己的配音或 MV 音乐，文字与声音对不上。

**方案**：
- 新增 `pipeline/asr.py`，后端可插拔：
  - **本地**：`faster-whisper`（CPU 可跑，需下载模型）——默认，不产生费用。
  - **云端**：走现有 provider 目录，计费入费用台账。
- 输出与现有 `subtitle_lines` 同构（`{start,end,text}`），复用现有保存/编辑/烧录/外挂链路，**不改下游**。
- 断句策略：按标点 + 最长时长 + 最小间隔，参数可调。
- 界面：字幕轨旁加「从音频识别」按钮，识别结果进入现有可编辑列表，**不直接覆盖**人工字幕（需确认）。

**能力诚实标注**：
- 本地 ASR 的准确率取决于模型与音质，必须显示"本地识别（未接入云端）"。
- 无音频时按钮禁用并说明"这条运行没有可识别的配音"。

**依赖**：无（可独立落地）。
**成本**：中（本地模型下载体积大；需处理首次下载与离线场景）。
**验收**：
1. 给一段已知台词的配音，识别文本与真值字符错误率低于阈值（记录实测值，不预设"很准"）。
2. 识别结果时间窗单调、无重叠、不超成片时长。
3. 识别后仍可逐行编辑、调偏移、重合成，行为与手写字幕一致。
4. 没有音频时明确禁用，不静默产出空轨。
5. 云端模式扣费入台账；本地模式费用为 0。

---

### C2 字幕样式模板 + 逐字高亮跨后端（P0）

> **落地状态（2026-11-16）**：**整句字幕样式已落地**——6 套预置、项目内独立样式版本、三画幅安全区排版、缺字检测与回退提示，换样式只重合成不重出图。**逐字高亮未落地**：当前只有整句时间轴，逐字时间来源（ASR 或 TTS 音素）尚未接入；绘制后端的整句字幕板仍用引擎自带纸感样式，C2 样式只作用于字幕卡后端。详见落地结果第 8 节。验收项 2 因此未完成，其余 1/3/4 已完成。

**剪映做法**：字幕预设（字体、字号、描边、阴影、位置、逐字高亮），可保存复用。

**本产品缺口**：样式散落在 `image_render` 与 painted 后端；painted 有逐字高亮，其他后端没有；用户不可配置。

**方案**：
- 定义 `SubtitleStyle`（字体族/字号/主色/描边色宽/阴影/底条/位置/最大行数/逐字高亮开关），存进项目 `plan/meta.json`，与品牌模板同级、独立版本号。
- 文字层渲染统一走一个 `render_subtitle_layer(style, text, t)`，所有后端共用。
- 样式变更只触发**重合成**，不重新出图（与现有字幕链路一致）。
- 预置 6 套模板（与现有色板呼应），支持"另存为项目模板"。

**能力诚实标注**：字体依赖系统/内置字体，缺字回退必须可见（不能静默变方块）。
**依赖**：C1 可选（样式与识别解耦）。
**成本**：中。
**验收**：
1. 6 套预置样式在 16:9/9:16/1:1 下均不溢出安全区。
2. 逐字高亮在非 painted 后端也生效（抽帧采样验证，参照现有 karaoke 工具）。
3. 改样式 → 只重合成，片段缓存不被判失效。
4. 缺字时有明确回退提示，不产出方块字。

### C3 导出预设与响度标准化（P0）

**剪映做法**：平台预设（抖音/快手/视频号）、码率、帧率、响度。

**本产品缺口**：只有画幅 × fit/crop；无码率/帧率/响度控制。

**方案**：
- 扩展 `TARGETS` 为 `ExportPreset`：画幅 + 分辨率 + 帧率 + 码率上限 + 响度目标（-14 / -16 LUFS）+ 容器。
- 预设：`抖音竖屏`、`视频号竖屏`、`B站横屏`、`通用高质量`、`通用小体积`。
- 响度标准化在 `mux_audio` 前对音轨过一次 loudnorm（已有 `mix_tracks` 的 loudnorm，可复用）。
- 导出面板显示预设说明（"抖音建议码率/响度"），不虚构平台硬性规范。

**能力诚实标注**：平台规范会变，界面标注"参考值"，不声称"官方认证"。
**依赖**：I3-B3（同画幅品牌导出）已落地。
**成本**：低。
**验收**：
1. 每个预设产物的分辨率、帧率、码率、响度实测落在预设区间。
2. 响度 -14 LUFS 预设的实测值与目标差 ≤1 LU。
3. 旧缓存键因预设加入而正确失效。
4. 预设不改变画面构图（仅规格与音轨处理）。

### C4 转场与文字动效（P1）

**剪映做法**：镜头间转场（叠化/擦除/推拉），文字入场/出场动画。

**本产品缺口**：硬切；文字静态。

**方案**：
- 转场：在 `concat_clips` 处改为按项目 `transition` 配置使用 ffmpeg `xfade`。**只提供 3 种**（叠化、左滑、黑场），且**转场消耗的时长从相邻镜头各扣一半**，总时长不变——这是与"分镜时长权威"兼容的关键约束。
- 文字动效：字幕层入场 0.2s 淡入/上移，由 `SubtitleStyle` 控制，默认关闭。
- 不做逐帧关键帧轨道。

**能力诚实标注**：转场会改变镜头可见时长（各扣 0.1–0.2s），界面必须标明。
**依赖**：C2（文字动效）、现有合成链。
**成本**：中。
**验收**：
1. 三种转场在片段边界可见（抽帧验证）。
2. 开启转场后总时长与分镜台账误差 < 0.3s。
3. 关闭时与现状逐像素一致（回归）。
4. 文字动效开关不影响片段缓存。

> **落地状态（2026-11-16）**：`compose` 支持 `transition`（none/fade/slide/black）与 `text_anim`。转场用 `xfade`：每个镜头在分镜时长两端补冻结帧（首个不补头、末个不补尾），补边正好占用转场前后半程，**镜头内容仍在原分镜时间轴上**；三镜各 2s 实测输出 5.967s（误差 0.033s），边界帧分别为混合/左右分屏/近黑。关闭转场继续走 `concat_clips` 的 stream copy，硬切边界无混合。文字动效是 0.2s 淡入，只作用于字幕卡，固定标题层不参与。界面新增「镜头衔接与字幕动效」面板，并写明各让出约 0.2 秒、总时长不变、转场需重编码。未做：文字上移/出场动画、转场时长可调、绘制后端（painted）不支持转场、浏览器点击实测。

### C5 音频闪避与对白优先（P1）

**剪映做法**：人声出现时自动压低背景音乐。

**本产品缺口**：只有固定 `music_gain`。

**方案**：
- `mix_tracks` 增加 `duck` 模式：用 `sidechaincompress` 以人声为侧链压音乐，阈值/压缩比/释放时间可配。
- 界面：混音面板加「对白优先」开关，默认关。

**能力诚实标注**：闪避是启发式，不是"智能识别说话人"。
**依赖**：现有混音链。
**成本**：低。
**验收**：
1. 人声段音乐电平下降 ≥ 预设 dB，静默段恢复。
2. 关闭时与现状一致。
3. 无配音时开关禁用。

> **落地状态（2026-11-16）**：`build_mix_args` / `mix_tracks` 已支持 `duck`，用 `sidechaincompress`（阈值 0.05 ≈ −26dBFS、比率 8:1、起音 20ms、释放 320ms）压垫乐；侧链键 `apad` 到整片长度，避免人声早结束把音乐尾巴截断。`audio_edit.voice_duck` 随项目保存，默认关，旧的 `audio_edit` 没有该字段时行为完全不变；拆解页混音面板有「对白优先（音乐自动闪避）」开关，MV（无配音）或无配乐时禁用并给出原因。真实 FFmpeg 验证（`tools/verify_audio_duck.py`，13 项通过）：人声段音乐 **−13.96dB**、静默段恢复 **+0.05dB**、未开启时人声段仅 +0.06dB、整片 5.000s 不截断。未做：阈值/压缩比可调界面（当前固定一套保守参数）、在浏览器中实际点击开关的人工验证。

### C6 节拍卡点界面化（P1，底座已有）

**现状**：`pipeline/beats.py` 已能估 BPM/首拍、按拍切镜、引擎接线，并有验证工具；但主要是 MV 路径。

**方案**：拆解页对 MV/配乐项目显示节拍网格，允许"按拍重排切点"，显示吸附前后时长对比。

**依赖**：无。
**成本**：低–中（主要是界面）。
**验收**：已有 `verify_beats.py` 结果作为底座，新增界面操作不改变总时长。

---

### C7 智能重构画幅（P2）

**剪映做法**：主体跟踪 reframe，横屏转竖屏时跟住人脸/主体。

**现状**：只有 fit/crop。

**方案（分两步，避免过度承诺）**：
- **第一步（轻）**：`crop` 增加"安全中心偏移"——允许用户为每镜指定裁切中心（左/中/右），解决"主体不在画面中心"的常见问题。无需模型。
- **第二步（重，需评估）**：接入人脸/主体检测做自动跟随。依赖模型与 GPU，成本高，**先不排期**，只留接口位。

**能力诚实标注**：第一步是"手动指定中心"，不是"自动跟踪"。
**依赖**：无（第一步）。
**成本**：低（第一步）/ 高（第二步）。

### C8 工程模板（P2，底座已有）

**现状**：品牌模板 + 撤销已具备。

**方案**：把"品牌 + 字幕样式 + 转场 + 混音预设 + 导出预设"打包成可复用工程模板，新建项目可一键套用。

**依赖**：C2、C3、C4。
**成本**：中。

## 4. 建议批次

| 批次 | 内容 | 理由 |
|---|---|---|
| **第 1 批** | C3 导出预设与响度 | 成本最低、直接提升交付质量、依赖已就绪 |
| **第 2 批** | C1 自动字幕（本地 ASR） | 补齐"声音驱动字幕"这条真缺口 |
| **第 3 批** | C2 字幕样式 + C5 音频闪避 | 提升质感，依赖 C1 的字幕链路更完整 |
| **第 4 批** | C4 转场与文字动效 + C6 节拍界面化 | 需严守"总时长不变"约束 |
| **第 5 批** | C7 裁切中心 + C8 工程模板 | 体验收口 |
| **暂不排期** | C7 第二步（自动跟随） | 依赖模型/GPU，先留接口 |

每批结束：全量自检 + 前端构建 + 对应真实产物验证，日志归档。

## 5. 明确不建议做（会破坏核心承诺）

| 剪映能力 | 不做的理由 |
|---|---|
| 自由多轨时间线 | 与"一句话重拍整片"冲突；一旦允许逐帧拖拽，分镜就不再是权威 |
| 逐帧剪辑 / 变速曲线 | 会改变分镜时长权威，导致台账、字幕、节拍全部失配 |
| 多层贴纸/自由关键帧轨道 | 复杂度指数上升，超出"分镜驱动"定位 |
| 云协作/云素材库 | 与本地优先、不上传用户素材的设定冲突 |
| 平台"官方认证"话术 | 无法核实，属于不诚实标注 |

## 6. 验收矩阵与诚实边界

| 功能 | 自动化 | 真实产物 | 人工 |
|---|---|---|---|
| C1 自动字幕 | 识别文本/时间轴回归 | 真实配音转写 | 准确率主观评估 |
| C2 字幕样式 | 三画幅安全区断言 | 抽帧确认样式/逐字高亮 | 目测 |
| C3 导出预设 | 分辨率/帧率/码率/响度断言 | 真实导出实测 | 目测 |
| C4 转场 | 总时长不变断言 + 抽帧 | 真实成片 | 目测节奏 |
| C5 音频闪避 | 电平包络断言 | 真实混音 | 听感 |
| C6 节拍 | 复用 `verify_beats.py` | MV 小样 | 目测卡点 |
| C7 裁切中心 | 构图偏移断言 | 真实导出 | 目测主体 |

**必须诚实标注的边界（延续既有约束）**：
1. 本地 ASR 的准确率不做"很准"承诺，只给实测数字；未接入云端时明确显示"本地识别"。
2. 平台导出预设是**参考值**，不声称官方规范。
3. 转场会占用镜头时长，界面必须显式说明。
4. 智能重构画幅第一步是**手动指定中心**，不是自动跟踪。
5. 任何依赖真实 GPU/模型的能力，在未实测前不得写进"已完成"。

## 7. 与现有迭代的关系

- C3 直接建立在 I3-B1/B2/B3（母版哈希、导出指纹、同画幅品牌）之上。
- C1/C2 复用现有字幕链路（`subtitle_lines` / `subtitle_mode` / 偏移 / 重合成），不改数据模型。
- C4/C5 改动集中在 `pipeline/compose.py`，必须配"关闭时逐像素一致"的回归。
- C6/C7/C8 建立在既有底座（beats/lyrics/brand/single-shot）之上，属于界面化与组合。

**本方案的定位**：不是"做一个剪映"，而是"把剪映里真正有用的几件事，按分镜驱动的约束，诚实地补进来"。
