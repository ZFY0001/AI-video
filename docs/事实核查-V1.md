## 一、硬错误（必须改，否则会误导技术决策）

### 1. Jev「33ms 延迟」是张冠李戴 ❌ → ✅

| | |
|---|---|
| 原文 | "T4 显卡上 33ms"、"单次 33ms"（技术方案 2.1、7 章；提示词库速查表） |
| 实情 | **33ms 是 Laya 的数字，不是 Jev 的**。Laya 是 Convai Innovations 的 421M 开源小模型，T4 上 p50 = 32.8ms。Jev 官方公布的托管 API p50 为 **236–276ms** |
| 影响 | 决策层延迟预算被低估约 8 倍；"300 次决策 ≈ 10 秒"的推算不成立（实际约 70–85 秒） |
| 来源 | [OrcaRouter: Jev vs Laya](https://www.orcarouter.ai/blog/jev-vs-laya) |
| 订正 | 技术方案改写为"官方公布托管 API p50 236–276ms；'33ms/T4' 一说实为 Laya 的数据，已剔除" |

### 2. Jev「开源权重」不成立 ❌ → ✅

| | |
|---|---|
| 原文 | "开源权重 + REST API + MCP 三种用法"、"自托管开源权重（laya 等）"（技术方案 2.1、5.1、6 章） |
| 实情 | **Jev 1.13 不是开源的**，TypeSafe AI 未发布任何权重，只能走托管 API。原文括号里的 "laya" 恰好就是被误当成 Jev 延迟数据的那个开源模型——**两者是不同产品** |
| 影响 | 原方案的"降级路径（自托管）"实际不存在，必须改为"更换供应商或回退为大模型" |
| 来源 | [OrcaRouter: is Jev open source](https://www.orcarouter.ai/blog/jev-open-source) · [docs.typesafe.ai/api.md](https://docs.typesafe.ai/api.md) |
| 订正 | 技术方案 5.1 改为"官方 REST API / MCP；**无自托管路径**"；6 章选型表"备选"由"无"改为"决策层可回退为大模型或本地规则引擎" |

### 3. REA「2026-10 爆火、12 万 Star」时间线错误 ❌ → ✅

| | |
|---|---|
| 原文 | "2026 年 10 月上线数天即获 12 万 Star"（技术方案 2.2） |
| 实情 | 仓库创建于 **2026-04-14**，npm 首发 **2026-07-12**；爆发在 2026 年 10 月第一周（10-09 的提交还在庆祝 3 万 Star，10-12 第三方报道 11.5 万）。**当前 215,055 Star / 52,999 Fork** |
| 影响 | "上线数天即 12 万 Star"是站不住的表述；应改述为"10 月第一周爆发式增长" |
| 来源 | [GitHub API](https://api.github.com/repos/morluto/rea) · [apidog 报道](https://apidog.com/blog/what-is-rea-reverse-engineer-anything/) |
| 订正 | 技术方案 2.2 改写时间线，Star 数标注"截至 2026-10-14" |

### 4. jevai.org 不是官方 API 宿主 ❌ → ✅

| | |
|---|---|
| 原文 | Base URL `https://www.jevai.org`；"key 在 /agent/keys 申请"（技术方案 5.1、提示词库 2 章开头与页脚） |
| 实情 | `www.jevai.org` 自称 **"Jev AI Community"** 社区站，页面上写着"Official docs and API live with TypeSafe AI"。**官方文档是 `docs.typesafe.ai`，官方 SystemOne 端点是 `POST https://api.typesafe.ai/v1/systemone`** |
| 补充 | `api.typesafe.ai` 在本次核查网络下**所有路径返回 HTTP 451**（不可用/法律限制），因此 Jev 的**实际可用性尚未验证** |
| 影响 | 决策层能否真正跑通，目前是**未验证状态**，不能写进方案当作既定能力 |
| 来源 | [jevai.org/docs](https://www.jevai.org/docs) · [docs.typesafe.ai/api.md](https://docs.typesafe.ai/api.md) |
| 订正 | 端点、鉴权、32 KiB 上限等**已确认无误**，但宿主区分官方/社区；管线 .env 默认值改为官方端点，并在风险表新增"Jev 可达性未验证" |

## 五、仍未验证的事项（诚实标注，不得当作事实使用）

1. **Jev 实际可用性**：`api.typesafe.ai` 在本网络返回 HTTP 451，未能发出任何真实请求；端点的**行为**（而非文档描述）未经实测。
2. **Jev 中文效果**：官方称英文最强，中文效果依旧**未验证**（与技术方案风险表一致）。
3. **单请求问题数上限**：官方未公布，不能引用"1-32"。
4. **Jev 官方发布日期**：仅第三方来源，未找到厂商公告。
5. **REA 官方工具数**：无官方数字，44 为本报告源码计数结果。
