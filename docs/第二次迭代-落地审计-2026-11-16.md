### I2-FE-01 保存屏障不完整 → 属实，本轮进一步收口

原实现：字幕、色板共用 `enqueue` 与 `revisionRef.current`，失败进统一 `noteSaveFailure`，保存中禁用拍摄。
**本轮审计后追加的收口**（均已落地 + 契约断言）：

1. **7 个保存域各自登记失败**：subtitle / palette / shot / script / subject / reference / order。`markSaved(domain)` 只销自己的失败记录，别的域还欠着就继续拦拍摄。
2. **`rewriteBusy` 整表重写锁**：重拆/恢复版本进行中，字段级失焦保存必须停手——它们带的是重写前的镜号与版本号，发出去要么 409，要么把刚重拆好的分镜改回旧值。`ActCard`/`SubjectCard`/`ShotEditor` 全部接 `locked`。
3. **409 整表读回**：`noteSaveFailure` 不只更新版本号，而是 `fetchPlan` 整份读回——否则屏幕上还留着被拒绝的那份编辑，用户以为它生效了。
4. **失败退回服务端值**：`saveShot`/`commitText`/`SubjectCard.commit` 在 `!ok` 时把字段重置为服务端值。
5. **正在输入的草稿不被回写冲掉**（本轮新增）：三处同步 effect 加 `focusedRef` 守卫。409 整表读回时，用户手上还没失焦的那一格保留，不被无声抹掉。

** deliberate 决策记录**：`replan` 与 `restore` **没有**走 `enqueue`。原因：replan 的 409 返回 `{kind:'need-force'}`，那是"要用户确认"，不是"保存失败"；若登记进 `failedSavesRef` 会永久阻断拍摄。两者都已先 `flushSaves()` 再置 busy 标志喂给 `editsBusy`。这是正确的例外，不是漏改。

## 6. 探针口径复核（两次假阳性，必须记录）

审计中两处"疑似缺陷"经复核为**测量环境造成**，不是代码问题：

1. **平滑滚动不动**：`visibilityState === "hidden"` 时浏览器暂停 smooth scroll，`scrollTop` 恒为 0。改 `behavior:'instant'` 后面板精确落在 124px（= `scroll-mt`），落点逻辑正确。
2. **暗色主题渲染成亮色文字**（算出对比度 1.07）：同一原因暂停 `transition: color .32s`，取到过渡中间值。注入 `transition:none!important` 后 body 为 `rgb(242,245,251)`，正确。**真缺陷是令牌值本身，不是主题切换。**

另有两类容易误判为溢出/缺陷的现象，已确立判定口径：

- **横向可滑条与抽屉内部滚动容器**会把子元素 rect 报到视口外，这不是文档溢出。统一用 `documentElement.clientWidth` vs `body.scrollWidth`，并向上遍历祖先查 `overflow-x`。
- **懒加载图片**在未进入视口时 rect 为 0，不能据此判"内容缺失"。

**结论：任何在后台标签页跑的视觉探针，必须先禁用过渡/动画再用 instant 滚动，否则结论不可信。** 本轮所有对比度与落点数字均在禁用过渡后取得。
