# 前端 UI 布局审计与落地改进方案

日期：2026-11-16（Asia/Shanghai）  
审计对象：一言片场当前 React 前端；本轮生产构建为 33 个模块，JS 389.01 kB、CSS 62.17 kB。  
审计重点：页面分区、任务优先级、操作可达性、窗口适配、信息密度与编辑效率。

## 1. 结论

**现有 UI 的视觉风格统一、页面功能齐全，但布局仍偏向“把新增功能依次往下放”。主要问题集中在主操作不可见、拆解编辑区出现过晚，以及成片详情在窄抽屉里承担了过多任务。**

建议保留现有配色、圆角、主题和主要业务能力，调整页面结构：

1. 创作台：基本输入与模式选择优先，主操作常驻，运行区按待命/运行/结果变化。
2. 拆解页：分镜成为首屏主内容；色板、动效、角色、音轨改为标签页、属性检查器或折叠配置。
3. 成片详情：快速预览用抽屉，完整复核/品牌/导出进入独立工作区；常用导出不经过整段逐镜复核列表。
4. 项目与任务：为多记录提供搜索、排序和紧凑列表；个人中心归入账号入口，拆解页提供项目路径与返回入口。
5. 全局：建立字号、间距、表面层级、焦点与断点规则，完善真实尺寸验收。

本轮整理 **11 项问题：5 项 P1、6 项 P2**。P1 表示影响主流程操作和核心编辑空间，应先改；不是后端安全等级。设置页已存在吸顶保存条、分区锚点、折叠原始诊断；窄屏主导航也已经存在，这些应保留，不重复报告为缺失。

本次没有修改业务源码，只新增审计报告、截图、布局测量、隔离页面数据和两份线框图。具体页面改造尚未实施。

## 2. 方法、范围与限制

### 2.1 实际检查范围

- 构建当前源码，运行本机隔离审计服务；数据在 `audit-artifacts/ui-layout-2026-11-16/fixture-data/`。
- 使用 6 个示例项目、3 个示例任务、8 镜/4 场/1 角色的拆解，测试有内容页面；示例视频仅用于占位，不代表生成质量。
- 实际查看创作台、项目、任务、成片墙、成片详情抽屉、设置、未登录个人中心和登录页。
- 用浏览器 CSS 视口检查 1340×880、1280×720、1080×720、390×844。前两类代表桌面常用视口，1080 对应桌面程序配置的最小窗口宽度；390 属 Web 窄屏补充检查。
- 记录元素边界、滚动高度、按钮位置，观察页面与实际键盘焦点。
- 类型检查和生产构建通过；本轮无业务代码改动，因此没有重跑完整后端自检。

## 5. 具体问题与可执行改法

### UI-01 · P1 · 主操作位于长表单底部，首屏无法启动流程

证据：[默认窗口截图](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/create-1340x880.jpg)，[操作区源码](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/CreatePage.tsx:658)。

现状：用户已填好主题，却需要滚过模式、时长、画幅、镜头时长、风格、色板、画质、帧率、绘制、真实模型、辅助线等条目才能点击开始。MV 的必要输入和主操作更深。高级设置与主任务使用了同样的纵向优先级。

改法：

- 第一屏保留主题、模式、时长/画幅/风格，以及能解释当前输出的“生成方式”。
- 色板、镜长、构图辅助、重试等归入高级设置；有明确用户需求时再展开。
- 选择代码绘制后才显示有效画质/帧率；生成方式开关在这些参数之前。
- MV/配乐的音轨与歌词紧跟模式选择，不放在整套高级参数后面。
- 操作条独立于长内容的滚动区域，“开始生成”为主操作，“先拆解”为次操作；显示输出概要和禁用原因。

验收：1080×720、1340×880 首屏始终可见至少一个主操作入口；高级默认折叠时，必填字段可在首屏完成；MV 的音轨入口不必先滚过无关参数。

### UI-02 · P1 · 1280px 断点使最小桌面窗口丢失配置/运行并视能力

证据：[双栏断点](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/CreatePage.tsx:274)、[状态面板固定最小高度](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/CreatePage.tsx:701)。

现状：只有 xl 才分两列。1080px 是项目允许的最小桌面窗口，但此时运行区被排到所有参数和操作之后；1340px 时右栏又因 items-stretch 跟随整块表单拉长，待命日志形成大空区。

改法：

- 桌面宽度从1024px起采用两栏：左侧 minmax(0,1fr)，右侧约320–340px；1280px以上允许右栏扩展到360–440px。
- 右栏 align-self:start；待命面板不以620px或整列等高撑高，改为最近结果、下一步提示或紧凑空状态。
- 运行后显示阶段/警告/停止，日志默认折叠，必要时展开并限定高度；结果回到同一预览区。
- 1024px以下切单栏时保留紧凑任务条；启动后可切到结果/进度标签，不把状态埋到表单末尾。

验收：1080px窗口内可以同时理解“我配置了什么”和“当前运行到了哪里”；待命日志区不占满整列；结束后不额外在长页面底部生成另一个难发现的结果区。

### UI-03 · P1 · 拆解页顶部单行状态/按钮挤压标题

证据：[1080px实拍](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/plan-1080x720.jpg)、[头部结构](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1572)。

现状：标题说明和 shrink-0 状态/按钮组争用同一行。1080px时标题说明只剩约61px，变成一条169px高的窄文本；390px时标题宽为0，按钮组延伸到995px。不是单纯字号偏小，而是空间分配规则有问题。

改法：

- 标题/面包屑占独立行，项目概要与低频时间记录放下一行或详情弹层。
- 顶栏只保留当前版本、保存状态和“更多”；低清预览/开始拍摄放常驻操作条。
- “只重合成”保留快捷可达，但可放入更多动作或根据当前修改类型突出显示；不要同时展开全部历史状态。
- 窄屏允许动作换行或明确更多菜单；不靠标题 min-width:0 无限收缩来容纳按钮。

验收：1080px时标题说明有可读宽度、正常两行内完成；390px无通用操作区横向溢出，页面主操作可见；按钮文字不被裁掉。

### UI-04 · P1 · 核心分镜被辅助设置推到首屏之外

证据：[当前拆解页](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/plan-1280x720.jpg)、[辅助设置顺序](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1699)、[剧本/分镜网格](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:2152)。

现状：色板 → 动效 → 角色 → 音轨 → 字幕轨 → 剧本/分镜。8镜示例1280px首镜输入y≈947；1080px又因剧本和分镜上下排列，首镜输入y≈1736。多数用户进入拆解页是改镜头，首先却要经过整套项目配置。

改法：

- 默认主区显示分镜列表，场次用筛选/导航；先让用户看到前两镜与状态。
- 剧本、字幕、音轨作为清晰标签页；色板/角色/动效放项目属性检查器或按需折叠。
- 有选中镜头时右侧展示属性，无选择时显示项目概要；保留当前行快速改时长/画面和单镜预览。
- 1080–1279px右侧属性面板可收起，不把整部剧本排在分镜之前；更窄时属性用抽屉。
- 30镜以上保留场次跳转、当前镜号和保存状态，不要求滚过所有设置后再找镜头。

验收：相同8镜数据在1080×720和1340×880都能首屏看到首镜可编辑内容；辅助配置可在一次切换/展开内访问；标签切换不丢未保存输入。

### UI-05 · P1 · 固定580px抽屉承载播放、复核、品牌和导出，任务链过长

证据：[详情首屏](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/history-drawer-1280x720.jpg)、[导出区](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/history-export-panel.jpg)、[抽屉尺寸](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css:1200)。

现状：在1280px窗口内抽屉仅580px，逐镜复核列表先于品牌与导出。8镜示例抽屉总高2671px，导出标题在2341px处。用户只想下载/导出，也要滚过不相关的复核表单。宽屏的左侧大量区域被遮罩锁住，编辑却只使用右侧狭窄空间。

改法：

- 轻抽屉只保留播放、时长/来源、下载原片、打开完整详情。
- 完整详情使用独立路由/工作区；上部视频，下部/右侧按“概览、质检、品牌、导出”分区切换。
- 第一屏提供下载/导出入口；复核列表不作为导出的必经滚动路径。
- 若暂不加路由，先改成宽版详情弹层（例如 min(1120px, calc(100vw - 48px))）并加标签页，先降低操作成本。
- 品牌的未保存状态与导出按钮就近显示；删除放独立危险操作区。

验收：打开成片后一次点击即可进入导出区；无需滚过8条复核；完整详情关闭/返回后保留成片墙筛选和滚动位置。

### UI-06 · P2 · 视觉弹层没有形成键盘交互边界

证据：[抽屉入口](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/HistoryPage.tsx:876)、[Escape处理](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/HistoryPage.tsx:575)。

实测：打开抽屉后焦点仍在背景第1个成片按钮，按Tab后移动到背景第2个成片按钮；drawer没有dialog角色或aria-modal。用户看到的是遮罩弹层，键盘却仍在操作背景列表。

改法：建立统一 Dialog/Sheet：打开时移焦到标题/关闭按钮，Tab循环留在弹层，背景 inert，关闭后焦点回触发元素；Escape保留。W3C的模态对话框模式要求焦点进入弹层且Tab不离开。[W3C模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

验收：仅用键盘完成打开、切标签、填写备注、关闭和返回；背景内容不可接收焦点；不要仅添加aria-modal却不实现行为。

### UI-07 · P2 · 信息字号与控件密度缺少统一层级

证据：[项目元信息](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/ProjectsPage.tsx:128)、[任务元信息](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/TasksPage.tsx:201)、[按钮尺寸](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css:414)。

重要版本、状态说明、时间与参数帮助中大量使用10–11.5px；成片详情把多种次要字段都放成同一层细字。代码ID与用户决策信息视觉权重接近。按钮已有34/28px两档，不能将它们直接判为不满足24px目标尺寸。

改法：

- 页面标题22–24px，分区标题15–16px，正文/输入14px，元信息/帮助12–13px；10–11px仅留非关键技术辅助，不作为所有说明默认值。
- 主操作36–40px高；图标按钮建议32px以上；触屏主要目标按44px设计（产品目标，不是本报告声称的WCAG最低尺寸）。
- 文本/边框/按钮对比在实际玻璃叠加后的背景上测量；不能只用CSS token就断言通过或失败。

验收依据：普通文本对比目标4.5:1、大文本3:1；目标尺寸最低24×24CSSpx有间距等例外，需逐项核查。[文本对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。禁用控件的浅色不直接计为对比失败。

### UI-08 · P2 · 背景、面板、输入和抽屉都使用半透明层，工作区层级不够稳定

证据：[导出区的背景穿透](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/history-export-panel.jpg)、[主题表面变量](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css:25)。

这是视觉审计判断：目前多个玻璃层、网格、光晕、阴影同时存在，区分“工作区、输入、可点击操作”依赖细边框；抽屉中还能看见背后卡片图像，长表单阅读负担增加。没有据此宣称整站已违反对比标准。

改法：保留品牌光晕和顶部玻璃，表单/编辑器用更稳定的不透明底；抽屉与详情提高底色不透明度，避免背景内容参与阅读；强调色集中在选中项、主操作和关键状态，不让每张卡都抢注意力。使用surface/base/raised/input/overlay五类明确token。

验收：明暗主题各截图检查表面层级；正常、悬停、聚焦、选中、禁用可区分；文本对比另做量化。

### UI-09 · P2 · 项目和任务以大卡片为唯一浏览形式，记录增加后效率下降

证据：[项目截图](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/projects-default.jpg)、[任务截图](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/audit-artifacts/ui-layout-2026-11-16/tasks-1280x720.jpg)、[项目网格](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/ProjectsPage.tsx:115)。

现状：3条示例任务已占据大部分首屏；6个项目可以浏览，但没有搜索和排序入口。该样本不等于实测20条任务性能，问题是布局的增长方式与查找能力不足。

改法：项目保留卡片并增加紧凑列表；任务默认使用64–88px高的摘要行，错误详情可展开；提供名称搜索、更新时间/创建时间排序、状态/模式筛选；用户可见标题优先，技术ID放复制/详情，错误摘要与恢复操作同一行。

验收：用20/100条合成记录测试，能按名称快速找到目标；切换筛选保持滚动/选择合理；长名称、长错误不会撑破操作列。搜索/分页超过已有接口能力时，再补后端查询参数，不默认重写服务。

### UI-10 · P2 · 拆解页缺少项目位置与返回路径，高频和账号入口未分层

证据：[导航激活逻辑](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/components/TopNav.tsx:139)、[个人中心双入口](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/components/TopNav.tsx:10)、[拆解返回按钮](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1614)。

现状：进入plan路由后不匹配任何全局导航项，项目来源不明显；主要返回按钮却是回创作台。导航又把个人中心和账号入口同时保留。Logo源码只滚动workspace，非创作页没有对应内容时不能提供可靠的快捷返回。

改法：全局高频入口保留创作/项目/任务/成片；设置与账号放工具区。plan归属项目导航，增加“项目 / 项目名称 / 拆解”面包屑；回项目保留筛选状态。Logo统一回创作台。手机导航已有实现，应继续保留可用性。

验收：从项目/任务/成片进入详情都有可理解的位置和返回路径；所有子路由有对应的激活主导航；不因分组调整丢失已有入口。

### UI-11 · P2 · 长页面缺少滚动提示，部分技术说明占据了操作文案

证据：[main隐藏滚动条](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/App.tsx:198)、[no-rail样式](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/index.css:1008)、[保存配置文案](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx:452)。

现状：主滚动区域隐藏滚动条，而关键操作/设置还在首屏之外；“.env”“runs/…”等实现名直接进入操作和提示。对维护者有意义，对创作用户不是完成任务的必要信息。

改法：恢复可见的细滚动条或明确区段导航；常用动作使用“保存配置、打开作品文件夹、移入回收区”，把文件路径放可展开的技术详情。设置页现有吸顶保存/锚点是好设计，应保留；重点是简化摘要和第一眼的状态，避免再加整套技术面板。

验收：长页面能看出当前所在位置与剩余内容；配置保存入口不依赖理解.env；错误信息包含可执行下一步，原始技术输出仍可查。

## 7. 组件和断点落地建议

### 7.1 第一批组件拆分

| 新组件/职责 | 当前来源 | 保持不变的业务契约 |
|---|---|---|
| AppShell / WorkspaceLayout | App + TopNav + main | 导航拦截、编辑保护、任务恢复 |
| PageHeader | 各页标题/状态/动作行 | 主体标题和当前状态 |
| WorkspaceActionBar | CreatePage/PlanPage重复操作 | 原start/plan/preview/recompose函数与保存屏障 |
| CreationBasics / AdvancedOptions | CreatePage长参数表 | FormState、模式与生成参数映射 |
| ShotWorkspace / ProjectInspector | PlanPage大页面 | revision、单镜保存、角色引用、字幕轨 |
| FilmDetail / ReviewTab / BrandTab / ExportTab | RunDrawer | 原媒体、品牌、质检、导出API |
| Dialog / Sheet | 当前overlay/drawer | Esc、关闭、编辑保护；新增焦点边界 |
| TaskRow / ProjectListRow | 任务/项目大卡片 | 状态、重试、继续编辑 |

切标签不应通过卸载组件丢失未提交表单；编辑状态保留在统一项目模型/保存协调器中。布局重构必须继续调用已实现的flush、revision与离页保护。

### 7.2 不只给长表单底部加一个sticky

推荐把操作条放到滚动内容之外：

```css
.workspace-frame {
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;
  height: 100dvh;
  overflow: hidden;
}
.workspace-scroll {
  min-height: 0;
  overflow: auto;
  scrollbar-gutter: stable;
}
.workspace-actions {
  padding-bottom: max(12px, env(safe-area-inset-bottom));
}
```

此代码是结构建议，不可直接覆盖当前App：TopNav、滚动ref、路由滚动复位和详情弹层挂载点需要一起调整。若先用fixed操作条，滚动内容必须预留真实操作条高度，确保最后输入与焦点不被遮住。不能只检查DOM里出现sticky/fixed就判主操作常驻，必须测量首屏位置。

### 7.3 响应式规则

| CSS视口 | 创作台 | 拆解 | 详情 |
|---|---|---|---|
| ≥1280px | 左表单 + 360–440px右栏 | 主编辑 + 320–380px检查器 | 完整详情工作区；轻预览仍可抽屉 |
| 1024–1279px | 左表单 + 320px紧凑运行栏 | 核心编辑优先，检查器可收起 | 宽详情/独立页面，避免固定580px承载全部 |
| 768–1023px | 单栏 + 运行概览条/结果标签 | 分镜优先，属性抽屉 | 标签分区，主要动作可换行 |
| 320–767px | 单栏与底部操作；已有窄屏主导航保留 | 标题独立，动作更多菜单；仅时间轴内部允许横滚 | 全屏详情，重要动作至少一次点击可达 |

窄屏应避免普通内容因布局而要求双向滚动；时间轴等本身需要二维布局的区域可单独处理。[W3C Reflow说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。本次实际测到390px，320px与200%/400%缩放仍列为实施验收项。

## 9. 验收清单

### 9.1 布局与任务效率

- [ ] 1080×720、1340×880首屏可见主操作；展开高级项或MV内容后仍可点击，不遮挡输入。
- [ ] 8镜/30镜拆解首屏出现首镜可编辑内容；核心编辑区不被角色/色板/动效堆到下方。
- [ ] 拆解标题不被压成竖排说明；320/390/768/1080px普通内容无横向溢出。
- [ ] 从成片详情一次操作到达导出区；不需要先滚过逐镜复核列表。
- [ ] 切标签/侧栏/页面时不丢未保存编辑；保存失败继续阻止拍摄或导出旧配置。
- [ ] 从项目进入拆解再返回，筛选、滚动和当前项目位置合理保留。

### 9.2 交互与视觉

- [ ] 模态打开移焦，Tab/Shift+Tab圈定，Esc关闭，焦点返回触发卡片。
- [ ] 主要字段有可访问名称，只有图标的操作有明确标签；小目标逐项检查尺寸与间距。
- [ ] 已完成/失败/停止/连接异常有文字表达，不只用颜色。
- [ ] 明暗主题的正文、状态、输入、选中、禁用、浮层分别检查；不靠“看起来浅”判对比失败。
- [ ] 200%缩放和320CSSpx重排测试完成；桌面默认与最小窗口测试使用真实内容尺寸，不以窗口外框代替。
- [ ] 原生成、预览、取消、字幕、版本、品牌、导出功能继续可用；前端类型检查和生产构建通过。

### 9.3 每个工作包的交付证据

保留修改前后同数据、同视口截图；记录主操作y位置、首镜y位置、横向溢出、到导出所需操作数；附关键交互回归。不要以截图漂亮或源码包含响应式class替代行为验收。
