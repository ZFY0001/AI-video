## 1. 项目定位

### 1.1 一句话定义

**输入一句话主题或一段文案，全自动输出一条成片**（画面 + 配音 + 字幕 + BGM）。中间不需要人工盯梢，管线自主完成编剧、分镜、绘图、视频生成、质检、重试、合成全流程。

### 1.2 要解决的问题

| 现状痛点 | 具体表现 |
|---|---|
| 决策疲劳 | 一条 3 分钟视频约 30 个镜头，每镜头都要判断"用哪个模型、这图合格吗、重试还是改词"，人工盯或全交给贵的大模型都吃不消 |
| 工作流黑盒 | ComfyUI 社区几十万个工作流 JSON 与编译版自定义节点没有文档，结构复杂，手写/改造门槛极高 |
| 废片不可控 | 生成结果质量波动，缺逐镜头质检与自动重试闭环 |
| 成本不透明 | 视频生成按条计费，试错成本高，"先试试这个想法"变成昂贵决定 |

### 1.3 与同类方案对比

| 维度 | 典型 AI 视频项目（如 Vibe Video 类） | 一言片场 |
|---|---|---|
| 创意 | 语言大模型写剧本/提示词 | 语言大模型（相当） |
| 决策 | 无专职决策层，人工抽检或 LLM 全包（贵） | **Jev 决策模型专责**，33ms/次，成本趋近于零 |
| 工作流获取 | 手写 JSON 或用固定模板 | **REA 逆向社区黑盒**，Agent 自动解析、改造、入库 |
| 执行 | 多为纯云端 API | 本地 ComfyUI 出图 + 云端视频 API 混合 |
| 质量控制 | 人工抽检 | Jev 逐镜头质检 + 自动重试闭环 |

## 2. 核心创新点

### 2.1 创新一：决策层外包给 Jev（快思考）

Jev 是 TypeSafe AI 于 2026 年 9 月发布的**决策模型**（System One 模型家族首个）：不生成内容，只做**选择 / 评分 / 分类**判断，一次前向传播输出类型化答案。厂商自述其托管 API 相比通用大模型 **193.6× 更快、444.6× 更便宜**（输出 token 免费），官方公布的托管 API p50 延迟为 **236–276ms**。接入方式为官方 REST API 与 MCP。

> **两处订正（V1.1）**：① 坊间流传的"T4 上 33ms"实为另一个开源模型 Laya 的数据（T4 p50 32.8ms），**不是 Jev**，本方案不予采用；② Jev **不是开源权重模型**，官方未发布任何权重，因此**没有自托管降级路径**。详见《事实核查-V1》。

把它放进视频管线，所有**高频、低价、判断性**的决策点全部外包：

| 决策点 | 输入 | 输出 | 频次（3 分钟/30 镜头） |
|---|---|---|---|
| 分镜模型路由 | 镜头描述 + 可用模型清单 | 选中的模型/工作流 | 30 次 |
| 生成质检 | 画面描述 + 验收标准 | 分数 + 接受/重试/拒绝 | 60-90 次 |
| 候选 N 选 1 | 分镜需求 + N 个候选 | 最佳候选索引 | 30 次 |
| 重试策略 | 失败原因 + 历史尝试 | 重试/改词/换模型/跳过 | 按需 |
| 上下文筛选 | 全部历史 + 当前镜头 | 相关片段子集 | 30 次 |
| 高危操作护栏 | 待调用的昂贵 API | allow/confirm/review/deny | 30 次 |

**合计约 300 次/条决策**。同样次数若用大模型，token 费用与延迟都可观；Jev 单次托管调用约 0.24–0.28 秒、输出免费。大模型只留在低频高价值的创意节点——**慢思考与快思考分离**，类比剧组里的"导演"与"场记"：导演一天导几场戏，场记每秒都在核对台词、服装、道具的连续性。

> **延迟预算订正（V1.1）**：按官方 p50 236–276ms 计，300 次决策约 **70–85 秒**（原先按 33ms 推算的"约 10 秒"作废）。这部分是**可并行**的：同一镜头的多个候选质检互不依赖，可并发提交，实际墙钟时间可压到镜头数的量级。

### 2.2 创新二：工作流黑盒逆向（REA）

REA（Reverse Engineer Anything，`github.com/morluto/rea`，MIT，TypeScript）是一个 MCP 服务器：把 Ghidra / IDA / Hopper / JEB / Apktool 等逆向工具封装成 Agent 可直接调用的工具（源码中可数出 44 个工具注册，官方未公布数字），本地运行，返回**带证据链**的结论（文件偏移、置信度、明确标注"未知项"），专治大模型幻觉。`npx rea-agents@latest setup` 一键接入 Claude Code / Cursor / Codex / Gemini CLI 等。

> **时间线订正（V1.1）**：仓库**创建于 2026-04-14**，npm 首发 2026-07-12，并非"2026 年 10 月上线"。爆发式增长发生在 **2026 年 10 月第一周**（10-09 的提交仍在庆祝 3 万 Star，10-12 第三方报道 11.5 万）；**截至 2026-10-14 为 215,055 Star / 52,999 Fork**。Star 数易变，引用时务必带日期。

ComfyUI 生态里最大的资产——社区分享的工作流 JSON 与编译版自定义节点（.pyd/.so）——恰恰是**最大的黑盒库**：没文档、结构复杂、改一处崩全局。用 REA 让 Agent 读懂任意工作流在干什么，并自动改造成项目所需版本，**工作流不再手写，而是逆向现成的**。这是别家视频管线都没有的一环。

### 2.3 创新三：全自动片场架构

| 角色 | 承担者 | 性质 |
|---|---|---|
| 编剧 / 导演 | 语言大模型 | 慢思考：剧本、分镜、提示词 |
| 制片人 | Jev | 快思考：路由、质检、筛选、重试 |
| 道具组 | REA | 黑盒解析：逆向工作流与自定义节点 |
| 摄影 / 后期 | ComfyUI + 视频大模型 | 执行：出图、出视频、一致性 |
| 剪辑 / 混音 | FFmpeg + TTS | 合成：拼接、配音、字幕、BGM |

## 3. 总体架构

### 3.1 架构分层

```
用户输入（主题 / 文案 / 脚本）
      │
      ▼
┌─────────────────────────────┐
│ 创意层 · 语言大模型（慢思考）  │  主题 → 剧本 → 分镜 → 每镜提示词
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 决策层 · Jev（快思考）        │  路由 · 质检 · 筛选 · 重试 · 上下文管理
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 执行层 · ComfyUI + 视频大模型 │  文生图 → 图生视频 → 角色一致性
└──────────────┬──────────────┘
               ▼
        成片 MP4（配音 / 字幕 / BGM）

┌─────────────────────────────┐
│ 解析层 · REA（离线）          │  逆向社区黑盒 → 可执行工作流模板库
└─────────────────────────────┘   （项目启动时运行一次，成果喂给执行层）
```

### 3.2 数据流：一次生成任务的完整旅程

1. 用户输入主题（如"给我的家乡方城烩面做一条 60 秒宣传片"）
2. 创意层 LLM 输出结构化 storyboard JSON（镜头清单 + 每镜提示词）
3. 决策层 Jev 为每个镜头路由执行方案（本地出图 or 云端视频、用哪个工作流）
4. 解析层提供的模板库保证第 3 步有现成工作流可用
5. 执行层按路由生成画面；Jev 逐结果质检，不合格进入重试闭环（重试/改词/换模型）
6. 全部镜头通过后，合成层拼接视频、合成 TTS 配音、烧制字幕、铺 BGM
7. 输出成片 + 全程决策日志（每一次 Jev 判断留痕，可回放审计）

## 4. 模块详细设计

### 4.1 输入层

- 支持三种输入：一句话主题 / 长文案 / 现成脚本
- 附带全局参数：时长、画幅（16:9 / 9:16）、风格基调、语言
- 输出标准化 `ProjectBrief`，作为创意层唯一输入

### 4.2 创意层（语言大模型）

职责：`ProjectBrief` → storyboard JSON。产出物必须是**结构化 JSON**，供下游程序消费，禁止自由文本。

Storyboard JSON 数据契约（模块间标准格式）：

```json
{
  "project": {
    "title": "方城烩面宣传片",
    "style": "烟火气、暖色调、纪实风",
    "aspect_ratio": "16:9",
    "total_duration": 60
  },
  "shots": [
    {
      "id": 1,
      "duration": 5,
      "narration": "方城人的一天，从一碗烩面开始",
      "visual": "清晨的老街面馆，门帘掀起，热气涌出",
      "camera": "固定机位，轻微推近",
      "prompt_image": "morning street noodle shop, steam rising, warm light, documentary style",
      "prompt_video": "slow push-in, steam drifting, subtle cloth movement",
      "subject_refs": ["shop_owner", "noodle_bowl"],
      "workflow_id": "wf_txt2img_sdxl_v3",
      "status": "pending"
    }
  ]
}
```

设计要点：

| 要点 | 说明 |
|---|---|
| 提示词双语 | Jev 与部分模型对英文支持更好，prompt 字段默认英文，narration 保留中文 |
| 主体引用表 | subject_refs 关联角色参考图库，保证跨镜头人物一致 |
| 工作流占位 | workflow_id 先由 LLM 预估，最终由 Jev 路由裁决 |
| 状态机 | status: pending → generating → reviewing → approved / rejected |

### 4.3 决策层（Jev）

Jev 的六类决策能力与管线决策点的映射（端点详见第 5.1 节）：

| 管线决策点 | Jev 端点 / MCP 工具 | 说明 |
|---|---|---|
| 分镜模型路由 | `POST /api/v1/decisions/model-route` / `jev_route_model` | 官方预设：传入 task + candidates（各带 id 与 description）+ priorities + stakes，返回选中的 candidate id |
| 任务分级 | `POST /api/v1/decisions/route` / `jev_route_task` | 返回 proceed_fast / deep_review / split_task / block，决定镜头是快出还是精修 |
| 生成质检 | `POST /api/v1/decisions`（原生，score + choice） | 按验收标准给候选画面打分，并判定 accept / retry / reject |
| 候选 N 选 1 | 原生 choice | 一次请求可带 1-32 个问题，N 张候选一次裁决 |
| 重试策略 | 原生 choice | retry_same / rewrite_prompt / switch_model / skip |
| 完成度检查 | `POST /api/v1/decisions/completion` / `jev_review_completion` | 交付前终检：目标是否真正达成 |
| 高危操作护栏 | `POST /api/v1/decisions/tool-guard` / `jev_guard_tool_call` | 调用昂贵视频 API 前评估副作用，返回 allow / confirm / review / deny |

设计要点：

| 要点 | 说明 |
|---|---|
| state 精简 | 请求体上限 32 KiB，只传与本次判断相关的信息（配合上下文预筛选） |
| 概率可解释 | 每次决策记录 choice / confidence / probabilities，形成审计日志 |
| 人工关卡 | 高 stakes 镜头（片头片尾、主角特写）保留 confirm 人工确认 |
| 中文待验证 | 官方称英文目前最强，关键 prompt 采用中英双语，上线前用标注样本验证中文效果 |

### 4.4 解析层（REA）

工作流逆向六步流程：

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1. 收集 | 从 OpenArt / Civitai / ComfyUI 官方示例等工作流 JSON 与自定义节点包 | 原料库 |
| 2. 静态解析 | REA Agent 读取 JSON，梳理节点清单、连线关系、参数表 | 工作流结构图 |
| 3. 语义理解 | 生成人类可读说明：用途、依赖的 checkpoint/节点、显存需求 | 工作流说明书 |
| 4. 改造 | 按项目需求改写：换底模、改分辨率、插入 ReActor / IPAdapter 节点 | 定制工作流 |
| 5. 验证 | 本地试跑；失败时 REA 证据链定位到具体节点/参数 | 可执行工作流 |
| 6. 入库 | 登记为模板（含来源、许可证、依赖清单） | 工作流模板库 |

合规边界（必须写入项目 README）：

- 只逆向**自己拥有或合法授权**的目标，不破解付费/DRM 内容
- 第三方工作流遵守其开源协议（GPL / MIT 等），注明出处
- REA 输出保留证据链，人工抽查关键结论

### 4.5 执行层（ComfyUI + 视频大模型）

本地 / 云端分工（依据：本机 RTX 4060 Laptop 8G 显存约束）：

| 任务 | 位置 | 理由 |
|---|---|---|
| 文生图（SDXL / FLUX GGUF 量化） | 本地 ComfyUI | 数量大、单价敏感、显存够 |
| 面部 / 角色一致性（ReActor、IPAdapter） | 本地 ComfyUI | 轻量节点，本地跑无额外费用 |
| 图生视频（SVD / 混元 / 可灵 / 即梦） | 云端 API | 显存不够，按需计费 |
| TTS 配音 | 云端 API 或本地 | 按质量要求选 |
| 合成（FFmpeg） | 本地 | 零成本 |

角色一致性方案（三级防护）：

1. **参考图锁定**：主体库预生成三视图/多角度参考图，每镜头携带 subject_refs
2. **节点级控制**：IPAdapter 风格迁移 + ReActor 面部保持一致
3. **决策级把关**：Jev 对"角色是否还是同一个人"做一致性质检，不过即重试

### 4.6 合成层

- 视频拼接：FFmpeg concat，支持转场参数
- 配音：TTS 按 narration 逐镜生成，时间轴对齐
- 字幕：烧制或外挂，样式模板化
- BGM：曲库匹配情绪标签，响度归一化（loudnorm）

## 5. 关键接口设计

### 5.1 Jev 接入

接入方式（二选一，可组合）：官方 REST API、MCP 工具（`jev_decide` 等，直接挂到 Claude Code 等 Agent 环境）。**注意：Jev 无开源权重，不存在自托管路径。**

官方 REST 约定（来源：`docs.typesafe.ai` 官方文档；社区站 `www.jevai.org` 内容一致但非官方宿主）：

| 项 | 内容 |
|---|---|
| 官方文档 | `https://docs.typesafe.ai`（社区站 `https://www.jevai.org/docs` 为镜像性质的社区资料） |
| 官方端点 | `POST https://api.typesafe.ai/v1/systemone`；社区站镜像 `https://www.jevai.org` |
| 鉴权 | `Authorization: Bearer <key>`，key 在 `/agent/keys` 申请 |
| 请求体上限 | 32 KiB |
| 响应封装 | `{ code, message, data }`，`code: 0` 为成功 |
| 可用端点 | `/decisions/tool-guard`、`/decisions/model-route`、`/decisions/route`、`/decisions/research`、`/decisions/completion`、`/decisions`（原生） |
| 模型版本 | 别名 `jev-latest`；公开模型 ID `typesafe/jev-1.13`；亦可通过 OpenRouter 等网关调用 |
| 问题类型 | choice（**最多 255 个选项**）、score（**2–10 级**，答案可为小数）、noul（0-1 的是/否概率）；**单请求问题数官方未公布上限**，官方鼓励批量提交 |
| 可达性 | ⚠️ 2026-10-14 核查时 `api.typesafe.ai` 全部路径返回 **HTTP 451**，Jev 的**实际可用性尚未验证**；决策层必须保留本地规则回退（本项目已实现） |

模型路由请求示例（贴合本项目场景）：

```json
{
  "task": "生成一个 5 秒方城烩面特写镜头：热气腾腾的汤碗，缓慢推镜",
  "candidates": [
    { "id": "comfy-sdxl-base", "description": "Local SDXL text-to-image, ~3s per image, near-zero cost" },
    { "id": "comfy-flux-gguf", "description": "Local FLUX GGUF quantized, best quality, ~8s per image" },
    { "id": "cloud-wanx", "description": "Cloud Tongyi Wanxiang, high quality, billed per image" }
  ],
  "priorities": ["quality", "cost", "latency"],
  "stakes": "medium"
}
```

生成质检请求示例（原生 decisions）：

```json
{
  "state": {
    "shot": " lamb soup close-up, steam rising, slow push-in",
    "acceptance": "subject sharp, no deformed bowl rim, warm tone, visible steam",
    "candidate_desc": "SDXL output: bowl centered, steam weak, slight rim deformation on left"
  },
  "questions": {
    "quality": {
      "type": "score",
      "instructions": "Score the candidate frame against the acceptance criteria",
      "criteria": ["reject", "marginal", "pass", "excellent"]
    },
    "verdict": {
      "type": "choice",
      "instructions": "Decide whether the candidate proceeds to video generation",
      "criteria": {
        "accept": "meets acceptance criteria",
        "retry": "minor issue, worth regenerating",
        "reject": "serious issue, rewrite prompt required"
      }
    }
  }
}
```

### 5.2 ComfyUI API 封装

- 提交：`POST /prompt` 携带工作流 JSON；监听 WebSocket 接收执行进度
- 封装为统一接口 `generate_image(workflow_id, prompt, refs) -> image_path`，屏蔽工作流细节
- 工作流模板库由 REA 解析层产出，运行时按 workflow_id 检索

### 5.3 REA 接入

- `npm install -g rea-agents`，`npx rea-agents setup` 注册到 Agent 环境
- 以 MCP 工具形式被 Agent 调用：读工作流 JSON → 输出结构说明 → 生成改造版
- 解析层作为**离线批处理**运行：启动项目时遍历模板库，产出说明书与定制版

### 5.4 语言大模型接入

- 统一走 OpenAI 兼容协议（或各家 SDK），模型可替换
- 系统提示词固化 storyboard JSON 契约，输出强制 JSON schema 校验

## 6. 技术选型

| 层 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 语言大模型 | Claude / GPT 级 | DeepSeek、通义 | 创意质量优先；需稳定 JSON 输出 |
| 决策模型 | Jev（官方 API / MCP） | 本地规则引擎或大模型（**无自托管权重**） | 类型化输出免解析、单次调用成本极低；备选用于 Jev 不可达时 |
| 文生图 | 本地 SDXL + FLUX GGUF | 云端万相 | 显存内最优、量大便宜 |
| 图生视频 | 云端 API（混元/可灵/即梦/Sora） | 本地 SVD（显存外备用） | 8G 显存跑不动高质量视频模型 |
| 一致性 | ReActor + IPAdapter | 参考图 + 后期筛选 | 节点成熟 |
| TTS | 云端 API | 本地 | 质量优先 |
| 合成 | FFmpeg | — | 事实标准 |

## 7. 成本与性能估算

单条 3 分钟视频（30 镜头）估算，单价以各服务当时价目表为准：

| 环节 | 调用量 | 成本量级 | 说明 |
|---|---|---|---|
| Jev 决策 | 约 300 次 | 趋近于零 | 输出 token 免费；**托管 API p50 236–276ms/次**，300 次约 70–85 秒（可并发压缩） |
| 语言大模型 | 3-8 次 | 低 | 剧本 1 + 分镜 1-2 + 提示词优化 2-5 |
| 文生图 | 30-90 张 | 低（本地电费） | 每镜 1 张 + 重试冗余 |
| 图生视频 | 30-60 条 | **高（主要开销）** | 云端按条计费 |
| TTS | 1 条 | 低 | 按字符计费 |
| 合成 | 本地 FFmpeg | 零 | — |

对比：若 300 次决策全部改用大模型，仅此一项成本即可超过整条视频的图像生成开销——**决策层外包是本项目成本结构成立的前提**（结论不变；订正的只是延迟量级，不影响成本论证）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **Jev 实际可达性未验证**（2026-10-14 核查：官方端点 `api.typesafe.ai` 全部路径返回 HTTP 451） | 决策层可能完全不可用 | 决策层**必须**保留本地规则回退（本项目已实现，规则与提示词库阈值表一致）；上线前先做连通性验证；保留更换供应商的抽象接口 |
| **Jev 无开源自托管路径**（官方未发布权重） | 无法本地部署降级 | 放弃自托管预期；降级路径改为"本地规则引擎 → 通用大模型" |
| Jev 中文效果未经证实（官方称英文最强） | 决策质量不稳 | 关键 prompt 中英双语；上线前用标注样本验证；预留降级路径（该层回退为大模型） |
| 角色跨镜头不一致 | 观感崩 | 参考图锁定 + ReActor/IPAdapter + Jev 一致性质检，三级防护 |
| 云端视频 API 限流 / 涨价 | 交付延迟、成本失控 | 多供应商抽象层；Jev model-route 动态路由；tool-guard 护栏 |
| 逆向工作流的许可证风险 | 法律合规 | 只逆向自有/授权目标；遵守开源协议；注明来源 |
| 本地显存 8G 瓶颈 | 出图慢、显存溢出 | FLUX GGUF 量化、SDXL 为主；视频全走云端 |
| Jev 请求体 32 KiB 上限 | 长上下文决策受限 | state 只传相关摘要（预筛选后再送 Jev） |
| 云端生成结果不可复现 | 迭代困难 | 全链路参数留痕，决策日志可回放 |
