### BE-01 · P1 · 任务接口绕过作品归属校验【HTTP 复现】

位置：[任务接口](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/app.py:131)、[事件流](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/app.py:164)、[任务视频](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/app.py:191)。

验收：主人可访问；其他账号与匿名用户无法列出、读取、订阅、取消或下载私有任务；不要仅覆盖 history 路由。

### BE-02 · P1 · 配置写入口匿名可用，键名检查不等于配置白名单【HTTP 复现】

### BE-03 · P1 · 权限查询失败时自动公开，归属记录失败被吞掉【故障注入复现】

位置：[归属查询与可见性](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/history.py:37)、[归属写入](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/auth.py:94)、[完成时归属绑定](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/jobs.py:106)。

`_owner_of()` 捕获所有数据库异常并返回 None，`_can_view()` 将 None 解释为公共项目。模拟 DB 故障后匿名 `_can_view()` 为 true。`record_run_owner()` 静默忽略失败，且普通生成任务到成功完成才绑定归属；运行期间、失败运行及归属写入失败都存在隔离缺口。

改进：将“明确公共”“未迁移”“归属查询失败”分开；查询失败默认拒绝并记录故障。在建立项目目录前预分配项目 ID、登记归属，再执行生成；失败和取消任务仍保留归属。对公共旧项目单独迁移，不再通过“记录缺失”推断公开。

验收：数据库不可用时私有内容不变成公共；失败和取消项目仍归原用户；归属持久化失败必须可观察。

### BE-04 · P1 · 拆解修改存在读改写丢失与临时文件竞争【并发复现】

位置：[JSON 写入](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:77)、[patch_shot](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:336)、[patch_script](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:284)。

每个请求先读整份 JSON，再更新并覆盖；没有项目事务或 revision 校验。探针让两个请求同时读取相同旧版本，并串行执行每次原子写入，以排除临时文件竞争干扰：两个请求均成功，但最终只保留一个镜头修改。实际 `_write` 还共用固定 `.json.tmp` 名，多请求可能争用同一个临时文件。

改进：单机先增加项目级读改写锁、唯一临时文件和 revision；请求携带期望 revision，冲突返回 409。涉及 storyboard/script/meta 的变更应在一个逻辑事务内提交。拍摄从不可变 revision 快照读取，禁止生成线程读到半套编辑状态。

验收：两个独立镜头编辑都保留，或其中一个收到明确冲突；meta 与正文一致；并发拍摄对应确定版本。

### BE-05 · P1 · 秒级运行 ID 可以碰撞并共用目录【标识生成复现】

位置：[new_run_context](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/config.py:222)、[创建拆解](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:229)。

ID 由“秒级时间戳 + 主题前 20 字”组成。固定同一秒、相同主题调用两次会得到同一 ID 和目录；主题前 20 字相同也有相同问题。`POST /plan` 不经过单任务 Registry，不能依赖渲染串行化防冲突。并发请求因此可能覆盖同一组文件；归属表的 INSERT OR REPLACE 进一步增加归属被替换风险。此处实际验证了标识和目录冲突，未使用两个真实用户实施覆盖。

改进：不可猜且唯一的项目 ID，展示标题单独保存；目录创建使用排他语义。所有创建入口支持幂等键，重试返回原项目，独立创建得到独立项目。

验收：同秒同主题并发创建 100 个项目，ID 和目录均唯一；重复幂等键不产生重复任务；归属不能被后续创建覆盖。

### BE-06 · P1 · 当前质检没有实际读取画面【源码与行为复现】

位置：[Pipeline._describe](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1243)、[模拟缺陷描述](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1547)、[规则评分](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/decide.py:199)。

### BE-07 · P1 · 音轨副本未成为重拍入口的恢复来源【行为复现】

位置：[拍摄入口音轨解析](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:649)、[运行内音轨复制](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:518)、[上传清理](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/media.py:112)。

### FE-02 · P1 · 失焦保存与拍摄未形成提交屏障【源码确认】

位置：[镜头失焦保存](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:249)、[保存请求](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:353)、[拍摄按钮禁用条件](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:476)。

文本框和镜长 onBlur 异步保存，但页面没有 pendingSave 计数或统一保存队列；拍摄只检查范围和 busyAct。编辑后直接点击拍摄，点击可能在保存完成前发起渲染，拍摄读到旧值。多个保存响应也没有 revision/请求序列保护。此项未做真实浏览器交互复现，属于明确存在的异步竞争路径。

改进：统一 dirty/saving/saved/error 状态；拍摄、重拍、重拆和离页等待 flushPendingEdits；前端串行提交同项目变更，服务端 revision 再兜底。保存失败保留输入和重试入口，避免直接回退导致丢稿。

验收：人为延迟 PATCH 2 秒，编辑后立刻拍摄，任务一定使用新 revision；保存失败时不启动拍摄。

### FE-03 · P1 · 事件流非终态结束后停止重连【模块复现】

位置：[readSse EOF](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/lib/sse.ts:63)、[useRun.connect](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/hooks/useRun.ts:111)。

readSse 在 reader.done 时正常返回；connect 随后 return，没有判断是否收到 done/error，也没有查询任务快照。模拟只发送 progress 后正常关流，Promise 正常完成，因此 UI 可能长期停留在 running。CRLF 输入的事件数为 0：先找 `\n\n` 再去 `\r` 的处理顺序无法识别 `\r\n\r\n`。当前后端发 LF，CRLF 问题主要影响协议兼容和替代流源。

改进：流结束后若未收到终态，先查快照，再按 cursor 重连；区分连接状态与生成状态。按行解析以正确处理跨 chunk、CR/LF 和多行 data；加入心跳超时，终态主动释放 reader。修 BE-01 时同步带认证头。

验收：中途 EOF、网络异常、终态前断线、CRLF、跨块边界均能恢复或给出明确状态；没有重复事件。

### FE-04 · P2 · 设置页无法清空已经配置的密钥【源码确认】

位置：[save](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/SettingsPage.tsx:89)。

保存前过滤所有 trim 后为空的值，因此把输入框清空不会发送清除指令，后端仍保留旧 Key。输入框初始为空又表示“不修改”，界面无法区分保留与删除。

改进：三态字段：未改动、设置新值、明确清除。提供“清除已保存密钥”，提交 delete 操作并返回字段状态，不回传密钥明文。

验收：配置、保留、替换、删除四条流程均可验证，清除后重新体检反映实际状态。

### FE-05 · P2 · 非法 hash 可使初始化抛错【原函数复现】

位置：[parseLocation](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/App.tsx:28)、[应用挂载](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/main.tsx:7)。

decodeURIComponent 无异常处理。用实际解析函数处理 `#plan/%` 抛 URIError；初始 useState(parseLocation) 期间可导致页面无法正常渲染，且没有应用错误边界。

改进：路由参数安全解码和格式校验；无效路由显示可返回入口的错误页；为页面和应用提供错误边界。保持简单 hash 路由也能修复，无需为此先引入新路由库。

验收：非法百分号、空 ID、未知路由、超长 ID 不白屏。

### FE-06 · P2 · 草稿恢复与认证相关状态需完善【源码确认】

位置：[CreatePage 局部表单](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/CreatePage.tsx:96)、[成片墙排除仅拆解项目](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/history.py:170)、[媒体 token](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/lib/api.ts:336)、[登录恢复](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/lib/auth.ts:120)。

创作表单只有页面局部状态，切页重建或刷新丢失。只拆未拍记录被成片墙过滤，缺少可浏览的草稿项目集合入口。媒体 URL 使用完整 7 天登录 token；恢复会话捕获任何错误都清 token，将临时网络故障与身份失效混淆。

改进：草稿项目库和自动保存；页面请求支持取消和旧响应丢弃；只有明确认证失败才退出。媒体使用短期、单资源受限凭据，避免在资源地址中携带完整账号凭据。完善对话框焦点、键盘操作与窄屏布局；本次不将未实测的视觉问题计为已复现缺陷。

验收：切页、刷新、重启能找回草稿；网络断开不会直接退出账号；媒体凭据仅能访问指定资源且短期到期。

## 5. 前后端进一步改进方案

### 5.1 前端目标结构

- **项目工作台状态**：projectId、revision、草稿、渲染配置、保存状态集中管理，页面只负责编辑与展示。
- **API 层**：统一认证、取消、超时、错误码和请求序列；从 OpenAPI 生成契约类型，减少手写类型漂移。
- **任务层**：连接状态与任务状态分开，订阅失败不直接等同生成失败；快照与事件相互校验。
- **编辑层**：可撤销变更、保存屏障、冲突处理；后续再逐步增加时间轴拖动。
- **界面层**：保留现有主题；将 CreatePage、PlanPage 的音轨、镜头、运行结果区域分成可测试组件。开发环境恢复 StrictMode 前先解决 effect 幂等与资源清理。

### 5.2 后端目标结构

当前规模建议继续使用 FastAPI + SQLite + 本地工作器；先解决数据与执行边界，不必立即引入微服务或分布式队列。

建议新增/规范化的实体：

| 实体 | 关键字段 | 用途 |
|---|---|---|
| projects | id、owner_id、visibility、title、status、current_revision | 所有归属与项目入口的真相来源 |
| project_revisions | project_id、revision、brief/script/board、render_profile | 保存、撤销、生成快照 |
| assets | id、owner_id、hash、path、type、duration、size | 稳定引用音轨、参考图、输出 |
| project_assets | project_id、asset_id、role | 引用保留与垃圾回收 |
| jobs | id、project_id、revision、state、progress、options、error_code | 重启恢复与状态查询 |
| job_events | job_id、seq、kind、data、created_at | SSE 重放、排障 |
| artifacts | job_id、type、asset_id、metadata | 成片、字幕、缩略图、质检证据 |

拆分职责：路由做协议与权限；服务层做项目事务、配置解析和任务提交；repository 做数据库/文件；worker 做步骤执行与取消；provider 做生成或技术检查。将 pipeline.py、painted.py 按规划、单镜生成、评审、音频、合成、绘制编译逐步拆分，先固定行为再移动代码。

### 5.3 性能改进顺序

1. 先记录每阶段时长、帧数、输出尺寸、缓存命中、峰值空间，建立本机基线。
2. 增加低清/低 fps 预览和单镜预览，确认画面后再输出正式规格。
3. 将缓存键明确绑定素材哈希、镜头内容、渲染配置、模板/字体/评审版本，区分画面变化和只改合成的变化。
4. 逐镜缓存绘制结果，使代码绘制也能逐步支持单镜复用；先保证边界连续，再考虑并行。
5. 历史元数据迁入 SQLite 后游标分页，避免每次遍历所有目录、读 JSON/日志和逐条查归属。
6. 对 FFmpeg/浏览器绘制设置全局并发、磁盘配额和工作器生命周期，避免无限制增加并发。

本轮没有测得新的秒/帧数据，不承诺未经验证的提速倍数。
