## 2. 逐项落地

### I3-B1 旧项目母版 manifest 回填 — 已落地

- 新增 `tools/backfill_masters.py`：默认演练，`--apply` 才写盘，自动跳过已有 manifest 与无成片项目。

### I3-B2 导出缓存键补内容哈希 — 已落地

- `server/exports.py`：`_content_sha()` 按 `path+size+mtime` 缓存实算哈希；`_fingerprint()` 改为 **manifest 哈希优先 → 实算 → 旧 size-mtime 兜底**；5 个调用点全部传入 `run_path`。
- 实测：导出记录的 fingerprint 已变为 `sha:ca63afd0…`（新格式）。
- 回归 3 项：同尺寸同 mtime 不同内容指纹不同；内容同、mtime 变指纹不变；品牌指纹参与缓存键。
- **一次性代价**：升级后既有导出缓存会因指纹格式变化全部失效一次（重导即可），这是换取"不产出错片"的必要代价。

|---|---|---|---|---|
| 抖音竖屏 | 1080×1920 | **30/1** | 0.72 MB / 12s ≈ 0.48 Mbps | 帧率与码率上限生效 |
| 小体积 | 1080×1920 | **24/1** | 0.34 MB / 12s ≈ 0.22 Mbps | 更小体积，符合预期 |

|---|---|

### 7.3 能力诚实标注

1. **码率是上限，不是恒定码率**。CRF 编码在简单画面下会明显低于上限（实测 0.48 Mbps vs 6 Mbps 上限），这是正常且更好的行为；界面不承诺"精确码率"。
2. **平台数值是参考值**。界面文案已写「参考值」，不声称官方规范；规范变化时只需改 `PRESETS`。
3. **响度只处理音轨**，不改变画面；无音轨时自动跳过。
4. 预设不改变构图与时长，只改编码规格与音轨电平。

### 9.3 能力诚实标注（未实测/未完成边界）

1. **闪避是启发式，不是“识别说话人”**。只要第 0 轨（配音）有能量就会压音乐，环境噪声、呼吸声同样会触发；多说话人场景不做区分。
2. **阈值/压缩比/释放时间目前固定**，界面只提供总开关；没有暴露参数微调。
3. **只有「人声 + 配乐」两轨时生效**。MV 模式（无配音）或没有配乐时开关禁用；打开但实际无配音时只写提示，不改变声音。
4. **响度归一在闪避之后执行**，最终响度仍以 `loudnorm` 为准；本轮未做“闪避前/后的主观听感”评估，只有客观 RMS 窗口测量。
5. 本轮未做浏览器内交互实测（开关点击、禁用态与提交参数仅经 `tsc`、构建与静态契约检查）。
6. 绘制后端（painted）的音频路径不经过本混音链，闪避对它不适用。
