# 一言片场 · Windows 使用手册

一句话进，成片出。输入一句主题或一段文案，程序自动完成：
**简报 → 剧本 → 分镜 → 出图 → 质检 → 重试 → 出片 → 配音 → 字幕 → 合成**

---

## 一、三种启动方式

| 方式 | 适用场景 | 前提 |
|---|---|---|
| **A. 双击 `启动客户端.bat`** | **推荐给所有人** | 原生窗口，装的是 `web/dist` |
| **B. 双击 `启动Web版.bat`** | 改前端、想在浏览器里开 | 同上；带 `rebuild` 参数会先构建 |
| **C. 命令行 `python -m server`** | 调试后端、看服务端日志 | 端口 8123 不被占用 |

### 客户端 vs Web 版，差在哪

两者跑的是**同一个后端**，只是外壳不同：

- **客户端**：`desktop.py` 在同进程里起 uvicorn，再用系统 **WebView2** 开一个原生窗口。
  没有地址栏、没有标签页，关窗即退。
- **Web 版**：起服务后调默认浏览器打开 `http://127.0.0.1:8123`。
  改前端时用这个，刷新就能看到效果，不用重启。

> 两个启动器都要求 `web/dist` 已构建。没有的话客户端会明确告诉你先跑
> `cd web && npm run build`，而不是开一个白窗口让你猜。

## 二、第一次使用（3 步出片）

1. **双击 `启动客户端.bat`**
2. 点顶部「**设置**」，看环境体检结论
   - `!` 开头是**降级提示**，不影响出片（详见第四节）
   - `✗` 才是真问题，按提示处理
3. 回到「**创作台**」→ 填主题 → 点「**开始生成**」

15 秒片子约 **35-45 秒**出片，中间日志会实时滚动（SSE 推送，不是轮询）。
出完在「**成片墙**」里能看到，点开就播。

### 出一支音乐 MV

1. 创作台 → 「**模式**」一行切到 `MV`
2. 填主题（这是画面内容的来源，不是歌词）
3. 把音频文件**拖进虚线框**（或点框选文件）。支持 mp3 / wav / m4a / aac / flac / ogg / opus，上限 60 MB
   - 传完框里会显示真实时长、体积与容器格式，这三个数都是服务端用 ffprobe 读出来的
   - 把 `.txt` 改名成 `.mp3` 会当场被拒——判据是「能不能解出音频轨」，不是扩展名
4. 贴歌词。可以直接粘进框里，也可以点「读 .lrc 文件」选文件
   - `.lrc` 最准，按时间轴对齐；纯文本按字数均分再吸附拍点
   - 歌词**只在你自己的浏览器里读**，不上传；读进来之后还能改
5. 节拍默认走「自动估计」（从音频里找 BPM，切点踩在拍上）。想更贴，关掉它手填 BPM 与首拍偏移
6. 「时长」一栏会变成只读，显示音频探测到的秒数——**MV 的总时长归音频管**，
   这里填多少都不作数，所以干脆不让填
7. 点「**开始生成**」或「**先拆解**」

> 音频超过约 40 秒时，框下方会提醒「会拆成约 N 镜」，勾了「代码绘制」还会给出预计耗时。
> 代码绘制约 1 秒/帧，3 分钟的歌就是几十分钟的量级——先拿一段 15 秒的试试手感。

要出「有解说、音乐只垫底」的片子，切到 `配乐` 模式，步骤完全一样，
只是时长仍按界面字段走、音乐短了会自动循环铺满。

## 三、界面说明

顶部四个导航入口，右上角是主题开关与账号入口。

### 创作台

- **主题 / 文案**：一句话就行
- **模式**：`解说` / `MV` / `配乐`。后两种会展开音轨面板；从 MV 切回解说会还回原来的时长
- **音轨**：拖放或点选上传，可替换、可移除。只在非解说模式出现
- **歌词**：粘贴或读 `.lrc` 文件；框下方显示行数
- **节拍**：「自动估计」默认开，关掉后可手填 BPM 与首拍偏移（秒）
- **时长**：5-600 秒。时长与镜头数成正比，长片耗时线性增长；MV 模式下这一栏只读
- **画幅**：`16:9` 横屏 / `9:16` 竖屏（短视频平台）/ `1:1` 方形
- **镜头时长**：默认 5 秒。镜头多则节奏快，镜头少则更沉稳
- **风格**：影响出图与配音节奏，可留空
- **画质 / 帧率**：只在勾了「代码绘制」时生效。低帧率换时间
- **代码绘制**：勾上就是 p5.js 水彩真画面，不勾是占位示意图
- **真实模型**：勾选后调用大模型（需先配置 Key）。不勾也能跑全流程
- **三分线参考**：生成的分镜示意图上画构图辅助线，供人工核对

底部两个按钮的分工很重要：

| 按钮 | 做什么 |
|---|---|
| **先拆解** | 只出剧本与分镜，**不渲染**。拆完进拆解页，可以逐场逐镜改 |
| **开始生成** | 一路跑到成片。中途也仍然可以回头看分镜 |

### 拆解页（`#plan/<run_id>`）

左边是场次，右边是这一场的镜头。能改的东西：

- 场次文字（改了以后这一场会被标成「待确认」）
- 单镜的时长、画面、机位、台词
- 时长越界**不会被静默修正**，直接拒绝并指出是哪一镜

MV 与配乐模式下，标题旁会多一个音轨徽章（`音轨 歌名 · 222s · MV`）。
它不只是装饰：从这个页面点「开始拍摄」只会传运行 id，歌词与节拍全靠拆解时
存下的那份记录回落——徽章是唯一能确认「我选的音轨还生效」的地方。

改完某一场的文字后，那一场会出现「**重拆这一场**」：只让模型重写这一场，
其余场次一字不动，**全片总时长锁定不变**。这一场若有你手改过的镜头，
会先问一次再覆盖（409 → 你确认 → `force`）。

### 改一镜、改时长，怎么不重拍整片

拍过一次之后，拆解页多出两个按钮。它们解决的是两种不同的不满意：

| 你嫌什么 | 点哪个 | 它干什么 | 要等多久 |
|---|---|---|---|
| **这一镜的画面不对** | 行内「**重拍这一镜**」 | 只重画这一镜，其余镜头沿用上次的片段，再整片重新合成 | 一镜的时间 |
| **时长或顺序不对** | 顶部「**只重合成**」 | 一个像素都不重画，只把片段按新时长对齐后重拼 | 几十秒 |

「重拍这一镜」不会重算时间轴——其余片段是按旧镜长渲出来的，镜长一动，
成片会从这一镜起整体音画错位，而且不报错。所以它只重排每镜的起点。

「只重合成」的代价是画面得迁就新时长：**改长了会冻结最后一帧，改短了会裁掉尾巴**。
这是"只重排不重画"的固有取舍——不想看到冻结帧，就点「重拍这一镜」或整片重拍。
对齐后的片段写在 `work/clips_fit/`，`work/clips/` 里的原始片段一个都不动。

镜头顺序用每一镜左上角的 ▲▼ 挪。镜号跟着镜头走、不随位置变：它同时是片段
文件名和"这一镜被改过"的记录，改号会把三处一起改坏。

> **代码绘制模式**下这两个按钮都用不了。它是按整段分镜编译成一条视频再逐帧渲染的，
> 既没有"只重画一镜"的入口，也没有逐镜片段可以重拼。点了会直接提示改整片重拍。

### 成片墙

每次运行的成片都留在这里，按用户隔离（游客看公共的，登录后多出"只看我的"）。
可以播放、跟着分镜走、看字幕、下载、删除。

> 删除是**移到 `runs/_trash`**，不是真删——删错了还能捞回来。

### 设置

- 填大模型 / Jev / ComfyUI / 云端视频 / TTS 的端点与 Key
- Key 输入框默认掩码显示，不会在屏幕上明文暴露
- 点「保存」写入项目根目录的 `.env`，立即生效
- 体检结果按三态展示：`✓ 就绪`、`! 已降级（不影响出片）`、`✗ 需修复`
- 体检含一项「FFmpeg 写盘」：只跑 `ffmpeg -version` 是不够的，某些受限终端
  （沙箱、受控环境、个别安全软件）允许执行 ffmpeg 却禁止它读写文件，
  版本探测通过但每一镜都会在出片阶段失败，且报错是误导性的
  `No such file or directory`。这一项会真实写一张 16×16 测试图来验证

### 个人中心

账号信息与用量统计（成片条数、总时长、占用体积）。

### 界面主题

右上角一键切浅色/深色，立刻生效，选择存在浏览器 `localStorage` 里。
令牌表在 `web/src/index.css`：浅色写在 `@theme` + `:root`，深色写在
`[data-theme="dark"]`。**深浅两套必须一一对应**——少一个令牌，
就有块地方在深色下白得刺眼，而且往往只在某一个页面上出现。

## 四、降级路径（为什么没配 Key 也能出片）

程序**不依赖任何单一外部服务**，每层都有兜底：

| 层 | 首选 | 没配/不可用时 | 出片影响 |
|---|---|---|---|
| 创意层 | 语言大模型 | 内置离线创意引擎 | 剧本偏模板化，画面不受影响 |
| 决策层 | Jev 官方 API | 本地规则引擎 | 阈值与升级规则完全一致 |
| 出图层 | 本地 ComfyUI | 离线占位帧合成 | **画面是分镜示意图，不是真实照片** |
| 出片层 | 云端图生视频 | FFmpeg Ken Burns 运镜 | 静帧加推拉摇移，观感可用 |
| 配音层 | 云端 TTS | Windows SAPI | 系统中文音色，可用 |
| 合成层 | FFmpeg | 无兜底（必需） | **没有 FFmpeg 无法出片** |

> **关于占位帧**：这是**分镜示意图**（构图、影调、镜号、字幕位齐全），用来验证
> 「分镜 → 画面 → 视频 → 成片」整条链路。帧上右下角明确标注「占位帧 · 未接入文生图」，
> 不会被误认成品画面。启动 ComfyUI 后自动切换为真实文生图。

## 五、接入真实能力

### 5.1 ComfyUI 真实文生图（强烈建议）
1. 装 ComfyUI 并下一个 SD1.5 模型，步骤见 [ComfyUI-Setup.md](ComfyUI-Setup.md)
2. 启动它（本项目根目录的 `启动ComfyUI.bat` 已带好参数，双击即可；
   或手动 `python main.py --port 8188 --disable-dynamic-vram --lowvram --reserve-vram 0.5`）
3. 点「环境体检」，显示「出图 comfy ✓」即已接入

**性能真相（8GB 显存必读）**
- 出图尺寸与成片尺寸解耦：出图长边钳到 640px（16:9 → 640x360），成片由 FFmpeg 放大到 1080p
- **千万不要把潜变量改成 1920x1080**——SD1.5 在 8GB 显存上会跑 3-10 分钟一张，还可能卡死在 VAE 解码
- `--disable-dynamic-vram` 必加：不加的话每次请求都重载模型，实测多花 300 秒/次
- 模型在 `models/checkpoints/` 的文件名必须与 `workflows/txt2img.json` 里 `ckpt_name` 完全一致

### 5.2 大模型创意（提升文案质量）
在「设置与环境」填写：
```
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=你的密钥
```
填完点「**保存到 .env**」，再点「**重新检测**」，看「大模型连通」这一行：
- `✓` — 密钥与端点都可用，勾选「真实模型」即可生效
- `✗` — 这一行会直接给出错在哪、怎么改，照着改完再点一次

**端点怎么填**（程序会自动补 `/chat/completions`，三种填法都能识别）：

| 你填的 | 实际请求 |
|---|---|
| `https://api.deepseek.com` | 补成 `/v1/chat/completions` |
| `https://api.deepseek.com/v1` | 补成 `/chat/completions` |
| `https://api.deepseek.com/v1/chat/completions` | 原样使用 |

常见服务商端点：

| 服务 | 端点 | 模型名示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` / `deepseek-reasoner` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` / `qwen-turbo` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 本地 vLLM/Ollama | `http://127.0.0.1:8000/v1` | 按你启动时加载的模型填 |

**接了 Key 却报错的对照表**：

| 体检里显示 | 含义 | 怎么改 |
|---|---|---|
| `HTTP 401 鉴权失败` | 密钥无效 | 检查是否复制完整（常见是少复制/带空格）、是否填到了正确字段 |
| `HTTP 404` | 端点或模型名不存在 | 端点要带 `/v1`；模型名换成服务商文档里的名字 |
| `HTTP 402 余额不足` | 欠费 | 充值或换服务商 |
| `HTTP 403` | 有密钥但无权/未实名 | 去服务商后台完成认证 |
| `HTTP 429 限流` | 请求过快 | 稍后重试 |
| `连不上…（检查网络/代理/防火墙）` | 网络不通 | 关代理、放行防火墙 |

**为什么之前"填了 Key 也看不出用没用上"**：早期版本体检只看「Key 非空」，
而且模型返回的 JSON 不合契约时会静默降级到离线引擎——成片照出，但文案很模板，
你根本查不出原因。现在这两处都改了：体检发真实请求验证，模型返回不合契约会
在运行小结里写明「创意层降级：…」及原因。

### 5.3 Jev 决策（项目核心差异点）
```
JEV_BASE_URL=https://www.jevai.org
JEV_API_KEY=你的密钥
```

> 未配置时走本地规则引擎，阈值与升级规则和提示词库完全一致，
> 功能不缺，只是少了「Jev 参与」这一层。

### 5.4 代码绘制后端（不用任何出图模型）

> 打包形态说明（EXE）：模板随包放在 `_internal/vendor/painted-template/`，但那是
> PyInstaller 的临时解包目录、只读，所以渲染时会把源码复制到
> `cache/painted/`，并用目录联接（junction，不需要管理员权限）把 `node_modules`
> 接过去。**必须联接**：`render.mjs` 用的是 ESM `import 'puppeteer-core'`，
> Node 解析 ESM 只从入口文件所在目录逐级向上找 `node_modules`，
> `NODE_PATH` 对 ESM 无效——没有联接会直接 `ERR_MODULE_NOT_FOUND`。
> 同理，`studio.html` 里 p5 的加载路径在打包形态会改成绝对路径去指模板目录。

生成页勾选「**代码绘制**」，成片会由 p5.js 水彩引擎**逐帧用代码画出来**——不调用
ComfyUI、不调用任何图像模型，也不下载权重。画面是水彩纸质感 + 墨线勾边。

**它是怎么工作的**

```
项目分镜（时长/机位/解说词）
   ↓  pipeline/painted.py 编译成 JS 场景
p5.js 场景文件（每一帧是时间 t 的纯函数）
   ↓  无头浏览器逐帧渲染（并行、可断点续渲）
JPEG 帧序列
   ↓  FFmpeg
成片 MP4
```

**它和别的后端有什么不同**

| | 代码绘制 | ComfyUI / Pillow |
|---|---|---|
| 画面来源 | 代码程序化绘制 | 扩散模型出图 |
| 角色一致性 | **天然保证**（角色是单一绘制函数） | 需靠提示词约束，不稳定 |
| 速度 | 慢（1 秒/帧量级） | Pillow 快，ComfyUI 中等 |
| 画面独特性 | 每条片都不重样 | 受模型风格限制 |
| 适合 | 短片、MV、需要固定角色的系列片 | 写实风、追求画面精细度 |

**你需要准备什么**

| 依赖 | 说明 | 没有会怎样 |
|---|---|---|
| Node.js ≥ 18 | 跑 p5.js 引擎 | 该模式不可用，其他功能正常 |
| Chrome 或 Edge | 无头渲染。**Windows 自带 Edge 即可**（Chromium 内核） | 同上 |
| p5.js / puppeteer-core | 随项目附带，无需自己装 | 同上 |

体检里有一行「**代码绘制**」，显示 `✓ 就绪 · Node · msedge.exe` 就说明能用。

**⚠️ 速度预期**：15 秒片 = 360 帧，本机实测约 **1100 ms/帧、4 线程并行 ≈ 7 分钟**。
这是水彩填充的固有开销，比 Pillow 慢一到两个数量级。渲染**可断点续渲**——中途停了
再跑会接着没渲完的帧继续，不用从头来。第一次建议先用「时长 6 秒 + 镜长 3 秒」试水。

**它不影响其他功能**：Node 或浏览器缺失时，这一项体检显示 `!`（不是 `✗`），
勾选「代码绘制」点开始会立刻弹窗告诉你缺什么，不会白等。

> 代码绘制后端源自开源项目 [tuzhechen2005/opus-video-skills](https://github.com/tuzhechen2005/opus-video-skills)
> 的 `painted-animation` 技能（MIT 许可，方法论来自 John Heibel 的 ClaudeAnimationBase）。
> 原技能是给 AI 当"写动画代码的说明书"，这里把它改造成可批量调用的渲染后端：
> 场景由分镜数据自动编译，无需为每个题材手写 JS。

## 六、FFmpeg 安装（必需）

体检若显示 `FFmpeg ✗`，或提示找不到，需安装：

1. 下载：https://www.gyan.dev/ffmpeg/builds/ （选 full_build）
2. 解压到任意目录，把 `bin` 目录加入系统 PATH
3. 或者：把 `ffmpeg.exe` 和 `ffprobe.exe` 放到**项目根目录的 `bin/` 下**，无需配 PATH

验证：命令行执行 `ffmpeg -version` 有输出即成功。

## 七、打包成 EXE

```bash
cd web && npm run build && cd ..   # 客户端装的是 web/dist，不先构建会打进旧前端
pip install pyinstaller
python build_web.py                # 默认 onedir（推荐）
```

产物：`dist/YiYanStudio-V4/`（**整个目录**拷走即可，分发时别漏 `_internal`）

- FFmpeg 默认随包（读项目根的 `bin/ffmpeg.exe`、`bin/ffprobe.exe`）；
  不想带就加 `--no-ffmpeg`，但目标机器得自己装
- 代码绘制的模板（`render.mjs` / `package.json` / `node_modules`）**整套随包**，
  否则打包版渲不出帧
- 成片、配置、日志都写在 **EXE 同级目录**的 `runs/` 与 `.env`

### ⚠️ 重要：为什么默认是目录模式而不是单文件 EXE

PyInstaller 6.x 的**单文件模式在路径含非 ASCII 字符（中英文等）时会报**

```
Could not load PyInstaller's embedded PKG archive from the executable
```

现象是**双击毫无反应、进程空转不退出、也不报错**。这不是本项目的 bug，
但会让"双击就打不开"的排查变得很痛苦。

因此默认使用 **目录模式（--onedir）**，它启动更快、不受此限制。
若你确认路径全为英文/数字，可以显式要求单文件：

```bash
python build_web.py --onefile
```

`build_web.py` 还会先把源码复制到 ASCII 临时目录再构建，从源头规避该问题
（顺带把 `vendor/.../out`、`.git` 这些不该进包的东西排掉）。

## 八、常见问题

**Q：双击了但"没反应"，窗口也没弹出来？**
双击 `启动Web版.bat` 而不是客户端——它留着命令行窗口，失败原因会打在里面。
最常见的两种情况：
- **缺 `web/dist`**：客户端会明说让你先 `cd web && npm run build`；
- **BAT 里被塞了中文**：`cmd.exe` 按 GBK 解析 `.bat`，UTF-8 中文会变成乱命令。
  本项目的启动脚本内容全是英文，若你自行改过，请保持纯 ASCII。

**Q：EXE 双击没反应、进程空转不退出？**
这是 PyInstaller 在**路径含非 ASCII 字符**时的已知问题（报
`Could not load PyInstaller's embedded PKG archive`）。现象就是无窗口、进程挂着。
解决办法：把整个 `YiYanStudio/` 文件夹移到纯英文路径，例如 `C:\YiYanStudio\`，再双击。
命令行加 `--selftest` 可确认是程序问题还是路径问题（会生成 `self_test_report.txt`）。

**Q：控制台中文乱码？**
命令行运行前先设 `chcp 65001`，或用 `python yiyan.py` 而非 `pythonw`。客户端窗口不受影响。

**Q：程序说「环境有问题」但能出片？**
看具体是哪一项标了 `✗`。常见是提示词库不同步——改完 `docs/提示词库-V1.md` 后需重跑：
```bash
python tools/extract_prompts.py
```

**Q：我填了自己的 API Key，还是报错/文案还是很差？**
分两步排查，一步都不能跳：

1. **确认 Key 真的生效了** —— 回「设置」点「**保存到 .env**」，再点「**重新检测**」，
   看「大模型连通」那一行。它会发一次真实请求，不是看 Key 非空就过。
   `✗` 时该行自带修复建议，按它改完再点一次。
2. **确认创作层真的用了模型** —— 勾选「真实模型」后再跑一次，看运行小结里
   有没有「创意层降级：…」。有这行说明模型返回的 JSON 不合契约（比如缺
   `narration_full`），程序已自动回退离线引擎——成片照出但文案会偏模板。
   把那行提示连同原因一起看，就能定位是提示词问题还是模型不听话。

另外确认两点：① 端点要带 `/v1`（填全 `.../v1/chat/completions` 也可以）；
② 密钥复制时不要带前后空格和换行。

**Q：体检显示橙色「环境受限」，说 FFmpeg 无法写盘，怎么办？**
这是**运行环境**限制，不是安装损坏。某些沙箱、受控终端、安全软件允许执行
ffmpeg 却禁止它做文件 I/O，此时版本探测会通过，但每一镜出片都会失败并报
`No such file or directory`（这个报错很有误导性，文件其实是在的）。
解决办法只有一个：**换普通环境运行**——
- 关掉受控终端/沙箱，用 Windows 常规的 PowerShell 或 CMD 启动；
- 若是安全软件拦截，把项目目录和 `bin\ffmpeg.exe` 加入白名单；
- 也可以把整个项目复制到 `C:\YiYanStudio\` 这类纯英文短路径再试。

判断依据：手动跑一次 `bin\ffmpeg.exe -f lavfi -i color=c=red:s=16x16:d=1 -frames:v 1 out.png`，
能生成 out.png 就说明环境没问题。

**Q：打包时提示 "No module named PyInstaller"？**
用错了 Python 解释器。用项目对应的解释器打包：
```bash
.venv\Scripts\python build_web.py
```
（`build_web.py` 会先检查 PyInstaller 再清理，不会再把已有产物误删）

**Q：配音比镜头长怎么办？**
日志和底部会提示「需人工关注」。缩短解说词或加大该镜时长即可。

**Q：成片里少了几个镜头？**
说明那些镜头终检未达标被剔除（宁缺毋滥原则），运行小结和日志会写明被剔除的镜号。

**Q：能跑多长的片？**
15 秒（3 镜）实测约 40 秒出片。3 分钟（30 镜）预计 6-8 分钟，线性增长。

**Q：程序崩溃了，日志在哪？**
分三层，从外往里看：

| 文件 | 内容 |
|---|---|
| `work/desktop.log` | 客户端启动日志。**开不了窗口先看这个**；写不进去时会退到系统临时目录的 `yiyan-desktop.log` |
| `runs/<run_id>/run.jsonl` | 这一次运行的逐条事件，出片出错看它 |
| 界面上的运行日志 | 与 `run.jsonl` 同源（SSE 推送），当场就能看到 |
