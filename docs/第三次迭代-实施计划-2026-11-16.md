### I3-B1 旧项目母版 manifest 回填

**问题**：`server/artifacts.py` `current_video` 对无 manifest 的旧项目回落 `output/final.mp4`，但**不回填**。实测 `20261020-234805-方城烩面` 的 master 视图为 `{"kind":"legacy","legacy":true,"sha256":"","artifact_id":""}`。后果：这批项目永远拿不到内容哈希与 artifact_id，导出缓存键与审计追溯对它们失效。

**方案**：
- 新增 `backfill_master(run_path)`：只在 `output/master.json` 缺失且 `output/final.mp4` 存在时写一份 `kind="legacy"` 的 manifest，`sha256` 实算、`created` 取文件 mtime、`artifact_id` 用 `legacy-<run_id>` 稳定生成。
- 触发点：`current_manifest` 读到 None 时**惰性回填**（读路径带写，需加锁避免并发重复写）；或提供 `tools/backfill_masters.py` 一次性迁移入口 + 启动时可选扫描。
- **推荐惰性回填 + 显式迁移工具双轨**：惰性保证任何入口访问即修复，工具保证可批量演练与回滚。
- 回填必须**幂等**且**不覆盖已有 manifest**；写入走原子 replace。

**依赖**：无。
**验收**：
1. 旧项目首次访问后 `master.json` 存在，`sha256` 等于 `final.mp4` 实算值，`legacy=true`。
2. 二次访问不重写（mtime 不变）。
3. 已有 manifest 的项目不被触碰。
4. `final.mp4` 缺失时不写空 manifest，仍返回 None。
5. 并发 10 次读只产生一份 manifest。
6. 迁移工具在**复制的**历史项目上跑通，原项目零改动。

**风险**：读路径带写会改变 `current_manifest` 的纯读语义，调用方若在多进程下访问需确认锁范围。缓解：锁按 run_path 粒度，与 `_project_lock` 一致。

### I3-B2 导出缓存键补母版内容哈希

**问题**：`server/exports.py` `_fingerprint`（[:88](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/exports.py#L88)）只用 `st_size + st_mtime_ns`。同尺寸同 mtime 的不同内容（复制、touch、原子替换后 mtime 巧合）会命中旧导出缓存，产出错片。

**方案**：
- 指纹改为 `sha256(母版内容)` + `brand_fp`。母版哈希优先取 manifest 的 `sha256`（I3-B1 回填后旧项目也有），缺失时实算并缓存到内存 LRU（按 path+mtime 失效）。
- **保留旧格式兼容**：无品牌且 manifest 无哈希时沿用 `size-mtime`，避免升级后既有导出缓存全部作废；一旦拿到哈希就切新格式并让旧缓存自然失效。
- 大文件实算耗时需实测：1.35 MB 样片可忽略，真实成片可能上百 MB，必须走"manifest 优先 + 惰性实算 + 缓存"。

**依赖**：**I3-B1**（旧项目要有 manifest 哈希才能免实算）。
**验收**：
1. 同尺寸同 mtime、内容不同的两个母版 → 指纹不同。
2. 内容相同、mtime 不同 → 指纹相同（缓存命中，不重复导出）。
3. 品牌指纹变化 → 导出缓存失效。
4. 无 manifest 的旧项目回落旧格式，不报错。
5. 百 MB 级母版首次实算耗时记录在案，二次命中不再实算。

### I3-B3 同画幅 + 品牌导出可达

**问题**：`TARGETS` 只有 `{"9:16","1:1"}`，16:9 原片加品牌水印时走 [:314](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/exports.py#L314) 的 `422 成片已经是 16:9，不需要再导出`。批量导出遍历 `TARGETS`，因此"16:9 + 品牌"这条组合**完全不可达**。

**方案**：
- 把"是否需要导出"的判据从**画幅相同**改为**画幅相同且无品牌且无变换**。同画幅但有品牌 → 照常合成（品牌层是真实变换）。
- `TARGETS` 增加 `"16:9": (1920, 1080)`，但**仅在源画幅非 16:9 或存在品牌/变换时**进入编码；源已是 16:9 且无品牌时仍跳过（避免无意义重编码）。
- 批量导出列表按"源画幅 + 是否有品牌"动态生成可达组合，不再无条件遍历 `TARGETS`。
- 前端导出面板对不可达组合给出明确文案，而不是让按钮点了报 422。

**依赖**：无（但与 I3-B2 同文件，建议同批改动减少冲突）。
**验收**：
1. 16:9 源 + 品牌 → 导出成功，产物含品牌层，分辨率 1920×1080。
2. 16:9 源 + 无品牌 → 跳过，不重编码，返回明确"无需导出"。
3. 9:16 源 → 16:9 fit/crop 两档均可达。
4. 批量导出列表只列可达组合，数量与文案一致。
5. 不支持的画幅仍 422，错误文案列出可达集合。

### I3-B4 离线镜头静帧与证据图一致性（诚实标注）

**问题**：`server/history.py` `_still`（[:191](file:///D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/history.py#L191)）优先 `frame_path` **仅当 `frame_is_clean`**；离线后端 `frame_is_clean=False`，于是回落 `work/frames/shotNN_clean.png`（重画的无字背景），而质检面板展示的是**候选证据图**（带字占位帧）。两者不是同一张。

**定性**：这是 I2-BE-02 的**设计取舍**，不是 bug——离线占位帧自带文字，无法直接作为运动背景。但用户看到"质检面板一张图、留存画面另一张图"会认为证据错位。

**方案（二选一，推荐 A）**：
- **A 诚实标注**：离线镜头的静帧旁明示"离线占位背景（非评审证据图）"，并在质检面板标注该镜为离线来源。不改图像选择逻辑，只消除误解。成本低、无产物风险。
- **B 双图并存**：同时保留证据图与干净背景，静帧展示证据图、视频用干净背景，界面提供切换。成本高，且会让"进入视频的图"与"看到的图"再次分裂——与 I2-BE-02 的初衷冲突。

**依赖**：无。
**验收（按 A）**：
1. 离线镜头静帧带来源标注，文案明确区别于真实出图。
2. 真实出图镜头静帧无该标注，且等于证据图（哈希一致）。
3. 质检面板的模式汇总与静帧标注口径一致，不出现"视觉评审通过"配"离线占位"的矛盾组合。

### I3-F1 编辑闸门的真实并发验证

**问题**：`rewriteBusy` 锁与 `focusedRef` 草稿守卫已落地 + 契约断言 + 静态核对，但**未在活场景下跑过**（审计未实测边界第 9 条）。

**方案**：在**临时复制项目**上构造真实并发：
1. 两个浏览器上下文同时打开同一项目；A 改镜 1 时长并保存，B 基于旧 revision 改镜 2 → B 收 409 → 验证 B 整表读回、字段退回服务端值、提示文案出现。
2. B 在镜 2 台词框**保持焦点并输入**，此时 A 触发 409 读回 → 验证 B 手上未失焦的草稿**不被抹掉**。
3. A 点"重拆这一场"，在重写进行中 B 尝试改字段 → 验证字段 disabled、重拆按钮 disabled。
4. 恢复版本进行中同样验证。
5. 字幕脏态下点拍摄 → 验证自动持久化先落地再 flush（与 I3-F2 合并跑）。

**依赖**：I3-P8（已落地）。
**验收**：5 个场景全部通过，且**临时项目验证后删除，用户原项目零改动**。
**约束**：不得在用户真实项目上构造 409。

### I3-F2 真实渲染下的字幕自动持久化与混音权威

**问题**：`startAction`/`restore` 先自动保存脏字幕再 flush 的逻辑已核对，但未在真实出片流程验证（边界第 10 条）；混音画面权威修复只跑了隔离 ffmpeg 素材（边界第 11 条）。

**方案**：在临时项目上跑一次完整离线出片：

5. 台账时长与成片实际时长一致（N-02 的核心验收）。

**依赖**：I3-P5（已落地）。
**验收**：5 项全过，`probe_duration` 与台账差值 < 0.3s。
**未覆盖**：真实 TTS 供应商音质、真实 GPU 出图质量——仍属边界。
