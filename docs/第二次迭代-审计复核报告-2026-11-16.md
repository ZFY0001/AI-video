### I2-BE-01 · P1 · 新生成任务归属失败仍继续，恢复后项目可能公开

位置：[Job._on_start](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/jobs.py:176)、[Job._record_owner](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/jobs.py:193)、[Engine._worker](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/app/engine.py:560)、[可见性](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/history.py:103)。

`record_owner()` 本身会抛错，但任务启动和完成回调捕获后仅记警告；Engine 还会吞掉 on_start 回调异常。读取故障确实返回 503，可一旦数据库恢复，始终未成功写入归属的项目会被解释成“公共旧项目”。

复现：使用独立数据库构造 Job，在 `_on_start` 注入 OwnershipUnavailable；回调正常返回、警告存在；故障移除后归属为 null，匿名 `_can_view` 为 true。不是“所有 DB 故障立刻公开”；条件是新项目归属登记失败且没有后续成功补写。

修复：所有生成入口先分配项目、提交归属和任务记录，再允许工作器写产物；失败返回 503，不进入生成。Engine 不吞业务前置失败。旧项目公开通过显式 visibility/迁移状态表达，不用记录缺失自动推断。

验收：注入归属写失败时生成器调用次数为 0；取消/失败项目仍归原主体；DB 恢复后匿名不可见。保留查询故障 503 的已修行为。

### I2-BE-02 · P1 · 本地视频没有使用已经选中并评审的生成图片

位置：[选定图片后出片](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1386)、[重新绘制 clean](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1571)、[Ken Burns 输入](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1629)。

`shot.frame_path` 指向已选中的生成图片，但 `_make_clip()` 为 Ken Burns 重新调用 `render_still(...with_text=False)`，将新画的分镜背景作为输入。真正使用 `shot.frame_path` 的只有其他视频 provider。于是 ComfyUI 出图 + 本地视频这条路径中，评审的图与进入视频的图不是同一张。

复现：假出图器产生可辨认图片，捕获本地视频 provider 输入：选图为 `generated-1.png`，编码输入为 `shot01_clean.png`，像素摘要不同。此验证不需要真实 GPU；没有声称本次跑过 ComfyUI。

修复：生成产物记录实际来源与选图 asset_id；真实生成图直接作为背景，只做尺寸/色彩适配；离线示意图的“无文字背景”由离线 provider 专门返回，不能对所有 provider 重画。文字作为单独合成层。

验收：给真实出图接口返回标记图，本地片段包含该标记；编码输入、评审图和选图共享同一资产链；fallback 来源准确显示。

### I2-BE-03 · P1 · 代码绘制结果与成片墙、导出使用的母版不一致

位置：[绘制输出位置](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/painted.py:1535)、[替换任务 compose](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/painted.py:1611)、[历史播放](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/history.py:580)、[导出源](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/exports.py:278)。

代码绘制将任务结果指向 `painted/final.mp4`；历史播放和导出仍固定读取 `output/final.mp4`。后者是绘制前保留的基础成片。因此用户可能在创作页看到绘制版，进入历史页或导出后得到基础版。

复现：在隔离项目中分别放置基础与绘制文件，调用实际 apply_painted（仅渲染器用替身）及导出源解析；任务结果为 painted/final.mp4，导出源仍为 output/final.mp4。

修复：建立唯一的当前发布产物指针/manifest；任务、历史、下载、封面、导出统一经过 resolver。保留基础版作为独立 artifact，不继续把固定路径当当前母版。历史项目做可回滚迁移，不能只按“painted 文件存在”猜版本。

验收：完成一条绘制片后，从任务、成片墙、重启后历史、下载和派生导出取到同一 master artifact；绘制失败时明确回落到基础版。

### I2-BE-04 · P1 · N 选 1 的图片与落盘质检证据不对应

位置：[循环覆盖 Shot 证据](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1268)、[候选选择](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1365)。

循环每次覆盖 shot.image_sha256、review_mode、technical 等字段。最后选择候选时仅切换 frame_path 和 quality，没有恢复该候选的完整证据。选到前面的候选，落盘仍保留最后一次尝试的图像哈希和技术记录。

复现：生成三个不同图片，固定选候选 1；frame_path 是 generated-1，image_sha256 却对应候选 3，摘要不一致。人工复核过期判断也依赖该摘要，因此受到影响。

修复：每个候选是完整对象，包含资产、输入、评分、模式、技术检查、模型/规则版本；选定后一次性绑定 evidence_id。结果发布前验证证据的图像摘要等于选中资产摘要。

验收：固定选第 1、第 2、第 3 候选分别核验；所有展示、人工复核和重新出片都引用同一 evidence_id；不使用最后一次循环状态代表最终选择。

### I2-BE-05 · P1 · 被拒绝的拍摄请求仍改写在用快照

位置：[freeze_plan](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:1384)、[先冻结](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:1532)、[后接纳任务](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/plan.py:1581)。

快照目录按 `rev-000000` 命名并直接覆盖文件。冻结发生在 Registry 判断忙碌之前。同 revision 改一次拍摄覆盖项，即使第二次请求最终返回 409，也已经覆盖第一次任务使用的 render_profile.json。快照目录保留策略也没有按活动任务引用保护。

复现：首次接纳默认 profile，记录快照文件摘要；第二次同 revision 请求 painted=true，模拟 Registry 忙碌；响应 409，但首次快照 profile 已变为 painted=true。

已证明不可变快照与可追溯性失效；没有扩大声称所有正在运行的参数都会即时变化，因为一部分配置已经捕获在 RunOptions 中。

修复：使用 task_id/唯一 snapshot_id；先预留任务槽位，暂存构建并校验快照，再原子发布和启动。拒绝请求不碰已有快照。清理根据任务引用和保留策略，不仅按最近 10 个目录。

验收：对活动项目连续发被拒绝请求、修改覆盖项、创建新 revision，原快照全部文件摘要不变且不被清理；任务结果可还原其 snapshot_id 与输入摘要。

### I2-BE-06 · P1 · 缓存漏实际输入，且命中过晚，无法兑现增量出图

位置：[clip_key 字段](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/clipcache.py:42)、[运行指纹](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1536)、[先出图再查缓存](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/pipeline.py:1237)。

两类独立问题：

1. `_locked_prompt()` 会将主体 visual_lock 拼入真正的图像提示词，但 clip_key 只包含引用 ID，不含主体锁定文字。实际出图提示词变了，缓存 key 不变；当前工作流内容、图像 provider 配置也没有进入依赖签名。
2. 每次 `_process_shot()` 仍先生成和评审，再到 `_make_clip()` 检查旧 MP4。探针第二次同输入运行：额外出图 1 次，额外编码 0 次。节省的是部分视频编码，而不是此前文档宣称的未变化镜头不重画；新增评审还可能代表新图，而视频仍是旧图。

参考图当前不被生成器消费，因此其文件哈希遗漏本身暂不构成当前图像条件输入失效；接入参考生成时才必须纳入，不能把未来风险说成现有参考图生效问题。

修复：分出生成缓存、评审缓存、片段缓存与合成缓存；昂贵生成前查生成签名，复用时同时恢复对应选图和证据。签名使用实际拼接提示词、真正使用的工作流内容、模型/端点规范化身份、被消费资产摘要与渲染版本；不能写入明文 API Key。故意排除时间轴起点/镜长的既有重合成规则保留，按 provider 的可复用语义管理片段长度。

验收：未变化正式重拍的出图/语义评审/编码调用均为 0；只改角色锁定让引用镜头失效，非引用镜头不变；改实际工作流/模型/被消费素材准确失效；只改时长仍支持 fit 后重合成。

### I2-BE-07 · P1 · 字幕编辑与视频烧录文字脱节

位置：[先合视频音轨](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/compose.py:299)、[随后只写 SRT](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/compose.py:308)、[MP4 视频流复制](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/pipeline/compose.py:111)。

人工字幕、清空轨和整体偏移影响外置 SRT/LRC；合成阶段没有用它们重建视频上的字幕。原字已在片段 overlay 或绘制层中烧录。只重合成复用片段时，用户改了字幕，视频仍显示旧字；清空外置轨也不能去掉已烧录文字。

复现：保持相同片段，分别传 NEW 字幕与空轨，实际 compose 函数执行后外置文件不同，进入视频 mux 的图像内容不变。探针对编码使用替身，只证明执行链未传入新字幕；没有把它冒充真实渲染目测。

这是“外置字幕编辑已完成、视频字幕更新未闭环”的功能缺口。如果产品只打算编辑外置文件，应明确更名和提示；根据现有上屏字幕与重合成流程，第二轮建议补齐统一字幕合成。

修复：保存不含字幕的画面母片；最终合成统一渲染字幕，明确 none/sidecar/burn/soft 模式。Pillow/代码绘制/MV 使用同一字幕时间轴，避免双重烧录。无需重出背景图即可修改字幕。

验收：修改、偏移、拆分合并、清空后抽帧验证实际 MP4；SRT/LRC 与画面一致；背景缓存复用；解说/MV/配乐、三画幅分别检查。

### I2-BE-08 · P2 · 同画幅加品牌被“无需重编码”规则阻止

位置：[单规格提前拒绝](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/exports.py:308)、[批量跳过](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/server/exports.py:371)。

源片为 9:16，目标也为 9:16 时，在读取品牌变换前就返回 422；批量也跳过。因此原生竖屏项目无法生成带品牌的竖屏版，虽该画幅属于当前 F7 的支持范围。

复现：隔离源片尺寸设为 1080×1920，并设置有效品牌；请求 9:16 fit，仍返回“成片已经是 9:16，不需要再导出”。

修复：只有画幅相同且没有品牌、字幕或其他输出变换时才可复用/跳过；有品牌应执行品牌合成。此发现不要求新增 16:9 品牌母版，该边界另列候选。

验收：原生 9:16 和 1:1 各自同画幅可生成品牌版；无任何变换时不重复编码；品牌修改、撤销与缓存失效正确。

## 5. 前端发现

### I2-FE-01 · P1 · 字幕和色板保存没有完整进入保存屏障

位置：[persistSubtitles](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:947)、[flushSaves](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1013)、[changePalette](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1047)、[startAction](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/PlanPage.tsx:1305)。

字幕直接请求 saveSubtitles，没有加入 chainRef；subBusy 不参与拍摄禁用。正在保存字幕时 startAction 能穿过 flushSaves，携带旧 revision=0 发起拍摄，随后字幕才保存成 revision=1。保存失败也不会进入同一失败登记机制。

色板虽然先等待 flushSaves，但等待之后读取闭包里的 `meta.revision`，不是实时 revisionRef；先前队列已经更新 ref 时，仍可能提交旧版本导致不必要 409。

复现：提取并执行实际回调，挂起字幕请求，随后调用 startAction；拍摄确实在字幕保存结束前发生。另一探针中 ref=1，色板请求提交 revision=0。

修复：所有项目编辑统一 coordinator，字幕、色板、角色、镜头等共用队列和实时 revision；失败保留 dirty 状态；拍摄、重拆、版本恢复与离页等待当前 dirty 字段真正提交。品牌可保持独立版本域，不必强行共用项目 revision，但导出必须等待本地品牌编辑提交或明确提醒。

验收：延迟/失败请求下立即拍摄均不会使用旧编辑；前后两个编辑不会互撞；错误修复后可继续；不要只检测源码里是否出现 flushSaves。

### I2-FE-02 · P2 · 已取消任务在创作页仍显示完成

位置：[done 事件](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/hooks/useRun.ts:99)、[快照归一](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/hooks/useRun.ts:119)。

后端以 done 事件传回 stopped=true 的取消结果，SQLite 状态是 canceled；前端见 done 一律 phase=done、stage=完成。applySnapshot 也只要 result 存在就判完成。任务中心和创作页因此不一致。

复现：执行实际 useRun hook，注入 result.stopped=true 的终态；最终 phase=done，stage=完成。

修复：统一任务状态映射，显式 canceled/interrupted；区分已停止、有部分产物、完整成功。事件与快照使用相同转换，不按有没有 result 推断成功。

验收：取消发生在准备、单镜生成、合成、绘制阶段，创作页、任务中心、刷新恢复均显示一致；有部分视频仍显示“已停止/部分产出”。

### I2-FE-03 · P2 · 混合质检模式的汇总会掩盖未评审或失败镜头

位置：[reviewNote](D:/02_Competation/01_AIC/YiYanStudio-V3-完整源码/一言片场-V3/web/src/pages/HistoryPage.tsx:564)。

只要任一镜头为 vlm，顶栏就选择“质检：视觉评审”，优先于 technical_failed 或 simulated。单镜详情有标签，这是已完成部分；汇总没有表达覆盖比例，容易把局部视觉评审理解为整片。

复现：实际汇总表达式输入 vlm/simulated/technical_failed 各一镜，输出仍为“视觉评审（多模态模型实际读图）”。

修复：按数量显示“视觉 1/3、模拟 1/3、技术失败 1/3”，不让单一模式代表混合结果；人工通过/驳回另计。技术通过与语义通过用不同字段。

验收：全视觉、全模拟、混合、失败、未记录五种组合；顶部、列表、导出前检查一致。
